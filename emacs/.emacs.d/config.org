* Introduction

This is a literate Emacs configuration. Everything Emacs actually
loads is generated from the ~emacs-lisp~ source blocks in this file:
~init.el~ tangles this file into ~config.el~ and loads that on every
startup (only re-tangling when this file is newer than ~config.el~).

To change my configuration, edit *this file*, not ~init.el~ or
~config.el~ — the latter is generated and any hand edits to it will
be silently overwritten on the next startup.

* Preamble

~org-babel-load-file~ tangles every block below into ~config.el~
with a leading ~:comments link~ line (per the file-wide
~header-args~ above), so the *first* line of ~config.el~ is normally
a comment pointing back to this file's headings, not a
~lexical-binding~ cookie. Emacs only honors that cookie on the
file's literal first line, and a trailing "Local Variables" footer
turns out to be unreliable for it too (Emacs warns that lexical-
binding set only at the end of a file can't be trusted, since
loading may already be underway by the time it's read). So this
block overrides ~:comments~ to ~no~, making it tangle as a bare first
line, matching every hand-written file in this directory and
avoiding the native compiler's dynamic-scope warning on ~config.el~.

#+begin_src emacs-lisp :comments no
;;; config.el --- generated from config.org -*- lexical-binding: t; -*-
#+end_src

* Package Management

We use the built-in =package.el= with MELPA added as a package
archive, plus =use-package= to declare and configure each package in
one place. =use-package-always-ensure= means every =use-package= form
below will auto-install its package if it isn't already present.

#+begin_src emacs-lisp
  (require 'package)
  (add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/") t)
  (package-initialize)
  (unless package-archive-contents
    (package-refresh-contents))
  (setq use-package-always-ensure t)
#+end_src

** Inherit the shell PATH (macOS)

A GUI ~Emacs.app~ launched from Finder/Dock/Spotlight -- or an Emacs
daemon started by =launchd= -- does *not* inherit the login shell's
=PATH=. It gets a bare =/usr/bin:/bin:/usr/sbin:/sbin=, which omits
Homebrew's =/opt/homebrew/bin=. That makes ~executable-find~ miss
~gpg~, so EasyPG's ~epg-find-configuration~ returns nil and opening any
=.gpg= file (e.g. =~/.authinfo.gpg=, which holds the FreshRSS Fever
password) fails with *"no usable configuration, OpenPGP"* -- even
though ~gpg~ works fine from a terminal. On Linux this never happens
because ~gpg~ lives in =/usr/bin=, which is always on =PATH=.

[[https://github.com/purcell/exec-path-from-shell][exec-path-from-shell]] copies the real shell =PATH= (and =exec-path=)
into Emacs at startup, fixing this for ~gpg~ and any other Homebrew
CLI tool. Guarded by ~system-type~ (not ~window-system~, which is nil
in a daemon frame) and wrapped in ~when~ so the shared =config.org=
never installs or runs it on the Linux box.

#+begin_src emacs-lisp
(when (eq system-type 'darwin)
  (use-package exec-path-from-shell
    :config
    (exec-path-from-shell-initialize)))
#+end_src

** Frame padding

A purely cosmetic change that does most of the work of making Emacs look
like a 2026 editor rather than a ported X11 application.

[[https://protesilaos.com/emacs/spacious-padding][spacious-padding]] adds
*internal* margins: space between the text area and the frame edge, padding
inside the mode line, and real window dividers. Emacs by default draws text
hard against the bezel with a zero-width internal border, and that density --
more than the colours or the font -- is what reads as dated next to Zed or
VS Code. No behaviour changes; only geometry.

It re-applies itself when the theme changes (it hooks ~enable-theme-functions~
internally), so ~C-c t~ (see [[*Themes]]) carries the padding across the
light/dark toggle with no extra wiring here.

~undecorated-round~ -- a macOS-only frame parameter (Emacs 29+, NS port)
giving the frame macOS's rounded corners and *no title bar* -- is left
**disabled** below, kept for reference in the same spirit as
[[*mood-line (disabled, kept for reference)][mood-line]].

It looks good, but removing the title bar also removes the traffic-light
buttons and the strip you grab to move the window, which is a poor trade
for a frame you actually drag around. Uncomment the two lines to try it;
the padding above is what does most of the visual work regardless.

#+begin_src emacs-lisp
(use-package spacious-padding
  :hook (emacs-startup . spacious-padding-mode)
  :custom
  (spacious-padding-widths
   '( :internal-border-width 18
      :header-line-width 4
      :mode-line-width 6
      :tab-width 4
      :right-divider-width 24
      :scroll-bar-width 8
      :fringe-width 10)))

;; Disabled: macOS rounded corners, but at the cost of the title bar --
;; and with it the traffic lights and the drag strip.  Uncomment to try.

;;   (add-to-list 'default-frame-alist '(undecorated-round . t)))
#+end_src

** Quiet async native-compilation warnings

Emacs 30 natively compiles installed packages *asynchronously in the
background*, lazily, the first time their files load after an install or
update. The compiler emits a "function X is not known to be defined"
warning for every cross-file forward reference it encounters -- routine
in any multi-file package (CIDER alone produces dozens) and harmless:
they are notes about compilation-unit ordering, not problems in the
package or in this config. By default each one pops the =*Warnings*=
buffer, burying whatever you were doing under noise every time a package
is installed or updated. ~'silent~ keeps the full log (see
~M-x native-comp-limple-mode~ / the =*Async-Native-Compile-Log*= buffer)
but stops the pop-up. Real *errors* in this config still surface
normally -- this only affects the background compiler's reports.

#+begin_src emacs-lisp
(setq native-comp-async-report-warnings-errors 'silent)
#+end_src

** Smooth scrolling through tall images

Line-based scrolling treats an image as a single tall "line": if it is
taller than the window, ~scroll-up-command~ cannot stop partway into it
and instead jumps clear past it to the next line -- so an article with a
big image (e.g. an Elfeed entry) skips the image entirely. ~pixel-scroll-
precision-mode~ scrolls by pixels instead, gliding smoothly through
over-tall images. It rebinds the mouse wheel / trackpad and
~PageUp~/~PageDown~; the keyboard ~SPC~ paging in ~elfeed-show~ is remapped
separately in the [[*Elfeed + FreshRSS (synced RSS)][Elfeed]] block.

#+begin_src emacs-lisp
(pixel-scroll-precision-mode 1)
#+end_src

** Fonts

Try JetBrainsMono Nerd Font first, then SF Mono, then Menlo (macOS's
own default monospace, always present), then whatever Emacs already
resolves to.

JetBrainsMono Nerd Font leads the list because it is the only candidate
carrying *both* a full weight family and a programming ligature set (see
[[*Ligatures]] for why the other installed fonts fail one or the other).
It is already ~framework~'s default mono under Omarchy; on macOS it is
not installed until =brew install --cask font-jetbrains-mono-nerd-font=,
and until then ~seq-find~ skips it and this resolves to SF Mono exactly
as it did before -- so the reordering is inert on this Mac right now.
Prefer SF Mono permanently? Move it back to the head of the list.

SF Mono is bundled *inside* apps like Xcode and Terminal but isn't
registered as a system font other apps can look up by name unless
it's separately installed (Apple distributes it standalone at
[[https://developer.apple.com/fonts/]]) -- so on a fresh machine
~(member "SF Mono" (font-family-list))~ comes back nil and this
falls through to the next candidate.

Critically, the height is set unconditionally, outside any font-
family check -- previously it was set only inside the ~when~ guard
above, so on a machine without SF Mono registered, the size never
applied either. Height is per-machine: this config is shared
between ~framework~ (130 / 13pt) and ~KevinsMacStudio~, whose
display needs 180 / 18pt to look the same size. ~system-name~
distinguishes them so one ~config.org~ can serve both without
editing this on every pull.

The same function also sets the proportional ~variable-pitch~ face --
used for prose body text in ~prose-mode~ (see [[*Prose Writing][Prose Writing]]) -- to
Apple's San Francisco text cut when installed. Both machines have SF
Pro, so prose looks consistent across them, and it degrades
gracefully to the generic sans elsewhere.

Daemon sessions can't do this at init time: the daemon starts with
no display, so ~font-family-list~ is empty and the default face's
family is meaningless -- baking those in is what garbled fonts in
~emacsclient~ frames. Under ~daemonp~, defer to
~server-after-make-frame-hook~, which runs once a real frame
exists (re-running per frame is idempotent and cheap).

#+begin_src emacs-lisp
(defun my/apply-font-settings ()
  "Set the default and variable-pitch face families for this machine.
Must run with a graphical frame live: in a daemon session
`font-family-list' is empty until a frame connects to a display.

The `variable-pitch' face is the proportional face `mixed-pitch'
switches prose body text to (see `prose-mode'); we point it at
Apple's San Francisco text face when present. \"SF Pro Text\" is the
body-optimized cut (as opposed to \"SF Pro Display\" for headline
sizes); the umbrella \"SF Pro\" name does not resolve, so the specific
cuts are named. When neither is installed the face is left alone,
falling back to its default \"Sans Serif\"."
  (let ((mono-font (seq-find (lambda (f) (member f (font-family-list)))
                             '("JetBrainsMono Nerd Font" "SF Mono" "Menlo")))
        (prose-font (seq-find (lambda (f) (member f (font-family-list)))
                              '("SF Pro Text" "SF Pro Display"))))
    (set-face-attribute
     'default nil
     :family (or mono-font (face-attribute 'default :family))
     ;; Per-machine default height (variable-pitch inherits this).
     :height (cond ((string-prefix-p "KevinsMacStudio" (system-name)) 180)
                   ((string-prefix-p "MWC9JXJTGDXD" (system-name)) 180)
                   (t 130)))
    (when prose-font
      ;; Family only: leaving :height unspecified lets variable-pitch
      ;; inherit the per-machine default height above, so `prose-mode's
      ;; text-scale bump still applies on top.
      (set-face-attribute 'variable-pitch nil :family prose-font))))

(if (daemonp)
    (add-hook 'server-after-make-frame-hook #'my/apply-font-settings)
  (my/apply-font-settings))
#+end_src

** Ligatures

Emacs 28+ shapes text through HarfBuzz, so a font's programming ligatures --
=->= or ==>= or =!== drawn as one connected glyph instead of two characters
butted together -- render correctly as soon as something tells Emacs which
sequences to compose. [[https://github.com/mickeynp/ligature.el][ligature.el]]
is that something. Scoped to ~prog-mode~, so prose and Org are untouched.

This pays off more in Clojure than in most languages: the threading macros
(~->~, ~->>~, ~cond->~) and the comparison operators turn up constantly, and
they are exactly the sequences these ligature sets are designed around.

*Ligatures only render if the active font actually contains them*, and the
fonts on this Mac are a mixed bag:

- =SF Mono= -- no programming ligature set.
- =MonoLisa Nerd Font= -- an excellent set, but only the *Regular* weight is
  installed here: no bold, no italic. With ~doom-themes-enable-bold~ and
  ~-italic~ both on (see [[*Themes]]), every bold or italic face would be
  synthesised by smearing and skewing the regular glyphs, which looks worse
  than the ligatures look good. Not worth the trade.
- =BlexMono Nerd Font= (IBM Plex Mono) -- all 16 weights, no ligatures.
- =JetBrainsMono Nerd Font= -- both: the full weight family *and* a strong
  ligature set. It is what ~framework~ already resolves to, and it is now
  first in the fallback list in [[*Fonts]] above.

So on macOS the one-time step to actually see any of this is:

: brew install --cask font-jetbrains-mono-nerd-font

Until that runs nothing changes: ~seq-find~ skips the absent family and
falls through to SF Mono exactly as before. Installing the font *is* the
switch -- no config edit needed. To keep SF Mono regardless, move it back
to the head of the list in [[*Fonts]].

     "<+>" "</>" "###" "..<" "..." "+++" "/==" "///" "_|_" "www" "&&"

* Themes

The default is ~doom-tomorrow-night~ (dark). ~C-c t~ toggles between it and
~doom-tomorrow-day~ (light), alternating from whichever theme is currently
active. Both ship *inside* the ~doom-themes~ package -- there is no separate
=doom-tomorrow-night=/=doom-tomorrow-day= package on MELPA, so trying to
~:ensure~ one fails with "package is unavailable". Themes are simply
~load-theme~'d below; ~custom-safe-themes t~ marks every theme trusted so
~load-theme~ never stops to prompt.

=themes/= holds ~logic-dark~, a hand-built local theme (neutral grays and
sparing accent hues sampled from Apple's Logic Pro X) that used to be the
default; it is no longer loaded, but =themes/= stays on
~custom-theme-load-path~ so ~(load-theme 'logic-dark t)~ still works if I
switch back to it.

#+begin_src emacs-lisp
(setq custom-safe-themes t)

;; Local themes (e.g. logic-dark) live here, next to the packaged ones.
(add-to-list 'custom-theme-load-path
             (expand-file-name "themes" user-emacs-directory))

(use-package doom-themes
  :ensure t
  :config
  ;; Global settings (optional).
  (setq doom-themes-enable-bold t
        doom-themes-enable-italic t)

  ;; Enable flashing mode-line on errors.
  (doom-themes-visual-bell-config)

  ;; Corrects (and improves) org-mode's native fontification.
  (doom-themes-org-config))

;; Load the default theme after doom-themes so its org fontification
;; is in place.
(load-theme 'doom-tomorrow-night t)

(defvar my/theme-toggle-list '(doom-tomorrow-night doom-tomorrow-day)
  "Themes `my/toggle-theme' alternates between.")

(defun my/toggle-theme ()
  "Switch between the two themes in `my/theme-toggle-list'.
Disables whatever theme is currently active first, so themes
never stack."
  (interactive)
  (let* ((current (car custom-enabled-themes))
         (next (if (eq current (car my/theme-toggle-list))
                   (cadr my/theme-toggle-list)
                 (car my/theme-toggle-list))))
    (mapc #'disable-theme custom-enabled-themes)
    (load-theme next t)
    (message "Theme: %s" next)))

(global-set-key (kbd "C-c t") #'my/toggle-theme)
#+end_src

** mood-line (disabled, kept for reference)

A lightweight, no-dependency replacement for the default mode line -- kept
around in case I switch back. ~:tangle no~ excludes this block from
=config.el= entirely (nothing to load/toggle at runtime); remove it to
re-enable, and comment out the ~doom-modeline~ block above instead.

mood-line deliberately omits minor-mode lighters, so ~prose-mode~'s
~" Prose"~ lighter would never appear. Since that mode substantially
changes how a buffer looks and behaves, we add a small custom segment
that surfaces it: ~mood-line-segment-prose~ returns an indicator only
while ~prose-mode~ is active (and nil otherwise, so mood-line drops
the segment and its separator entirely). It is spliced into a copy of
the default format on the right side, just before the major mode.

#+begin_src emacs-lisp :tangle no
(use-package mood-line
  :config
  (defun mood-line-segment-prose ()
    "Mode-line indicator shown only while `prose-mode' is active."
    (when (bound-and-true-p prose-mode)
      (propertize "✍ Prose" 'face 'mood-line-status-info)))

  (setq mood-line-format
        (mood-line-defformat
         :left
         (((mood-line-segment-modal)                  . " ")
          ((or (mood-line-segment-buffer-status) " ") . " ")
          ((mood-line-segment-buffer-name)            . "  ")
          ((mood-line-segment-anzu)                   . "  ")
          ((mood-line-segment-multiple-cursors)       . "  ")
          ((mood-line-segment-cursor-position)        . " ")
          (mood-line-segment-scroll))
         :right
         (((mood-line-segment-prose)      . "  ")
          ((mood-line-segment-vc)         . "  ")
          ((mood-line-segment-major-mode) . "  ")
          ((mood-line-segment-misc-info)  . "  ")
          ((mood-line-segment-checker)    . "  ")
          ((mood-line-segment-process)    . "  "))))

  (mood-line-mode))

* Icons

[[*doom-modeline (active)][doom-modeline]] already pulls in
[[https://github.com/rainstormstudio/nerd-icons.el][nerd-icons]] and its font
is installed per-machine via ~M-x nerd-icons-install-fonts~ (see that
section) -- but only the mode line uses any of it. These three extend the

* Custom Keybindings

~C-c r~ reloads the configuration without restarting Emacs. It
loads ~user-init-file~ (~init.el~), which reloads ~custom.el~ and
then runs ~org-babel-load-file~ on ~config.org~ -- re-tangling it

guaranteed-clean state, restart the daemon:
~systemctl --user restart emacs~.

** God Mode

God-mode lets me invoke ~C-~/~M-~ bound commands without holding
modifier keys: while it's active, plain key presses are interpreted
as if Control were held (e.g. ~xf~ runs ~C-x C-f~), and a leading
~g~/~G~ switches the next key to Meta/Control-Meta.

The toggle is bound to ~<f13>~, a keysym no physical key normally
sends. Caps Lock is remapped by ~keyd~ (system-wide, see
=/etc/keyd/default.conf=) to send Control when *held* and F13 when
*tapped* — so Caps Lock keeps working as Control everywhere else on
the system, and a bare tap now toggles God mode in Emacs instead of
reaching for the far-away Escape key.

This machine's X11 keyboard model is ~pc105+inet~ (see
=/usr/share/X11/xkb/symbols/inet=), which remaps the physical F13
position to the ~XF86Tools~ keysym instead of plain F13 — some
toolkits report that event to Emacs as ~<Tools>~ rather than
~<XF86Tools>~. Both symbols are bound below so the toggle works
regardless of which name the display stack reports.

The cursor switches to a box while God mode is active and back to a
bar otherwise, mirroring vim's normal/insert indicator, so it's
obvious at a glance which mode is active.

#+begin_src emacs-lisp
(use-package god-mode
  :bind
  (("<f13>" . god-mode-all)
   ("<Tools>" . god-mode-all)
   ("<XF86Tools>" . god-mode-all))
  :config
  (defun my/god-mode-update-cursor ()
    (setq cursor-type (if (or god-local-mode buffer-read-only) 'box 'bar)))
  (add-hook 'god-mode-enabled-hook #'my/god-mode-update-cursor)
  (add-hook 'god-mode-disabled-hook #'my/god-mode-update-cursor))
#+end_src

* Prose Writing

A distraction-free environment for long-form prose (a book, essays),
loosely modeled on Ulysses on macOS. Rather than hooking these into
every =org-mode= buffer -- which would drag agenda files, notes, and
this config itself into proportional fonts and a narrow column -- they
are bundled into a single ~prose-mode~ minor mode I toggle on
demand with ~C-c w~, or auto-enable per file with a "Local Variables"
footer (see below).

Three packages supply the pieces:

- *Olivetti* narrows and centers the text to a fixed column, the way
  Ulysses frames the page. ~olivetti-body-width~ is the column width
  in characters; 66 sits in the classic 45--75 "measure" for
  comfortable prose (80 reads long -- that's really a code width).
- *mixed-pitch* switches body text to a proportional font while
  keeping tables, code, and other fixed-pitch faces monospaced -- so
  prose reads like a book but structure stays aligned.
- *org-modern* restyles headings, lists, and markup for a cleaner,
  less-marked-up look.

#+begin_src emacs-lisp
(use-package olivetti
  :custom
  (olivetti-body-width 66))

(use-package mixed-pitch)

(use-package org-modern)
#+end_src

~prose-mode~ turns all three on together, plus soft line wrapping
(~visual-line-mode~) and typewriter-style scrolling that keeps the
current line near the vertical center (~scroll-conservatively~ with a
half-window ~maximum-scroll-margin~). Toggling it back off restores
each minor mode and clears the buffer-local scroll/spacing overrides
with ~kill-local-variable~, so the buffer returns to ordinary editing
rather than leaving stray locals behind.

Prose also runs one step larger than the default face via
~text-scale~ (buffer-local, so it never touches other buffers). The
Mac Studio already opens at an 18pt default, so it gets no bump;
=framework=, at ~13pt, gets a single ~text-scale-mode-step~ (~1.2x)
for a slightly more comfortable reading size. Because it is a
per-buffer zoom rather than a global font change, ~C-x C-=~ / ~C-x
C--~ still nudge it further while I write.

#+begin_src emacs-lisp
(defvar my/prose-text-scale
  (if (string-prefix-p "KevinsMacStudio" (system-name)) 0 1)
  "Extra `text-scale' steps `prose-mode' applies to the buffer.
Each step scales the buffer font by `text-scale-mode-step' (1.2x
by default).  KevinsMacStudio already runs a large 18pt default
face and gets no bump; framework gets one step over its ~13pt.")

(define-minor-mode prose-mode
  "Toggle a distraction-free prose writing environment.
Enables Olivetti, mixed-pitch, org-modern, soft line wrapping,
typewriter-style centered scrolling, and a buffer-local font bump
of `my/prose-text-scale' steps -- all in the current buffer only."
  :init-value nil
  :lighter " Prose"
  (if prose-mode
      (progn
        (olivetti-mode 1)
        (mixed-pitch-mode 1)
        (org-modern-mode 1)
        (visual-line-mode 1)
        (text-scale-set my/prose-text-scale)
        (setq-local line-spacing 0.3
                    scroll-conservatively 101
                    maximum-scroll-margin 0.5
                    scroll-margin 99999))
    (olivetti-mode -1)
    (mixed-pitch-mode -1)
    (org-modern-mode -1)
    (visual-line-mode -1)
    (text-scale-set 0)
    (kill-local-variable 'line-spacing)
    (kill-local-variable 'scroll-conservatively)
    (kill-local-variable 'maximum-scroll-margin)
    (kill-local-variable 'scroll-margin)))

(global-set-key (kbd "C-c w") #'prose-mode)
#+end_src

To have a specific manuscript open straight into ~prose-mode~, add a
file-local footer as the *last* lines of that ~.org~ file:

#+begin_example
# Local Variables:
# eval: (prose-mode 1)
# End:
#+end_example

Emacs will offer to mark the ~eval~ form safe the first time I open
the file; accept it and the mode activates automatically on every
visit thereafter -- while leaving every other Org file untouched.

** Folding a Section From Its Body

Plain ~TAB~ / ~org-cycle~ only fold when point is *on* the heading
line, so from inside an entry's body text I would first have to
jump up to the =*= headline. When drafting long prose I am almost
always in the body, which makes that round-trip a nuisance.

~my/org-fold-current-subtree~ folds the subtree containing point from
anywhere inside it, leaving point on the now-folded heading (the body
it was in is hidden, so landing on the visible headline is the
predictable result). It is bound to ~C-c f~ in Org buffers only --
=C-c C-,= is deliberately avoided, as Org binds that to
~org-insert-structure-template~. The binding is deferred with
~with-eval-after-load~ because ~org-mode-map~ does not exist until Org
has loaded.

#+begin_src emacs-lisp
(defun my/org-fold-current-subtree ()
  "Fold the subtree containing point and move to its heading.
Works from inside an entry's body text, not just on the heading
line the way plain `TAB' / `org-cycle' require."
  (interactive)
  (org-back-to-heading t)
  (org-fold-hide-subtree))

(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c f") #'my/org-fold-current-subtree))
#+end_src

* Spell Checking

[[https://github.com/minad/jinx][Jinx]] instead of the built-in Flyspell. Jinx checks the whole visible
window in one pass via the [[https://abiword.github.io/enchant/][Enchant]] library (falling back to a
compiled C module, ~jinx-mod~, built on first load), so it stays fast
where Flyspell's per-word ~ispell~ subprocess chugged. ~global-jinx-mode~
replaces *both* ~flyspell-mode~ and ~flyspell-prog-mode~: Jinx decides
what to check from face, so in programming buffers it limits itself to
comments and strings automatically, no per-mode setup.

Prerequisites (both machines): =libenchant= + =pkgconf= + a C compiler.
On macOS that's ~brew install enchant~ (Enchant then routes to the
installed aspell/hunspell dictionaries and macOS's native AppleSpell);
on Debian/Ubuntu, ~apt install libenchant-2-dev pkgconf~. Enchant is the
one moving part -- without it the ~jinx-mod~ compile fails on first use.

~M-$~ (normally ~ispell-word~) is rebound to ~jinx-correct~ -- correct the
word at point, or with a region/prefix the misspellings around it. ~C-M-$~
runs ~jinx-languages~ to switch dictionaries on the fly.

#+begin_src emacs-lisp
(use-package jinx
  :hook (emacs-startup . global-jinx-mode)
  :bind (("M-$"   . jinx-correct)
         ("C-M-$" . jinx-languages)))
#+end_src

** Lisp jargon dictionary (Clojure + Elisp comments)

Jinx checks comments as prose, so ordinary Lisp/Clojure/Emacs jargon in a
comment -- ~nREPL~, ~defn~, ~sexp~, ~docstring~, "jack in", ~eglot~ -- gets
flagged as a misspelling next to genuine typos, which is noisy rather than
useful. ~jinx-local-words~ is Jinx's own escape hatch for exactly this: a
buffer-local, space-separated list of extra words to accept, normally set
via ~.dir-locals.el~ for one project. Setting it from a *major-mode hook*
instead means every Clojure and Elisp buffer gets the list automatically --
including brand-new projects -- with no per-directory file to maintain.
Real typos elsewhere in the comment, and in prose/Org buffers, are still
caught; this only widens the dictionary for these two modes.

Jinx splits hyphenated/dotted identifiers into pieces before checking each
one -- ~cider-repl~ is checked as "cider" and "repl" separately, not as one
token -- so the list below spells out lowercase pieces explicitly rather
than relying on a single capitalized form like ~REPL~ to also cover ~repl~.

~jinx-local-words~ is defined *inside* the ~jinx~ package, which we load
lazily (~:hook (emacs-startup . global-jinx-mode)~ above, so it doesn't
slow down startup). Attaching this hook function directly at top level
raced that: an early buffer's major-mode hook (the startup ~*scratch*~
buffer's, in particular) can fire *before* ~jinx~ has actually loaded,
referencing a variable that doesn't exist yet -- ~"Symbol's value as
variable is void: jinx-local-words"~. Wrapping the whole thing in
~with-eval-after-load~ guarantees ~jinx-local-words~ already exists by
the time this code runs at all. The trailing ~dolist~ catches the one
remaining gap: buffers that were already open (mode hook already fired)
before ~jinx~ finished loading -- it applies the dictionary to those
directly, once, instead of waiting for a hook that already ran.

#+begin_src emacs-lisp
(with-eval-after-load 'jinx
  (defun my/jinx-add-lisp-jargon ()
    (setq-local jinx-local-words
                (concat jinx-local-words
                        " nrepl nREPL repl REPL sexp sexps"
                        " defn defns defun defuns docstring docstrings"
                        " eval evals evaluatable evaluatably"
                        " cider CIDER clj clojure Clojure ClojureScript"
                        " deps edn babashka bb"
                        " kondo eglot flymake lsp LSP"
                        " paren parens parenthesis parenthesized"
                        " slurp slurping barf barfing splice raise"
                        " kbd elisp Elisp defvar defcustom")))
  (add-hook 'clojure-ts-mode-hook #'my/jinx-add-lisp-jargon)
  (add-hook 'emacs-lisp-mode-hook #'my/jinx-add-lisp-jargon)
  (dolist (buf (buffer-list))
    (with-current-buffer buf
      (when (derived-mode-p 'clojure-ts-mode 'emacs-lisp-mode)
        (my/jinx-add-lisp-jargon)))))
#+end_src

* Programming Languages

** Rust

Built-in Emacs 30 pieces only -- no third-party mode or LSP client. This adds
three genuinely separate layers, each doing a different job, which is worth
untangling since their names get used interchangeably in casual Emacs talk:

1. *Major mode* (~rust-ts-mode~) -- decides how the buffer looks: syntax
   highlighting, indentation, which characters are "word" boundaries. This is
   the same job ~emacs-lisp-mode~ or ~org-mode~ does; it does *not* understand
   Rust *semantics* (types, what a symbol refers to) at all.
2. *Language server* (~rust-analyzer~) -- a separate background *process*,
   installed via ~rustup~ (not part of Emacs), that actually understands Rust:
   it type-checks, finds definitions, and computes completions by reading the
   whole project via =Cargo.toml=. ~eglot~ (built-in since Emacs 29) is the
   client that starts this process and speaks LSP (the standard JSON-RPC
   protocol nearly every editor uses) to it.
3. *Diagnostics display* (~flymake~, built-in) -- eglot forwards rust-analyzer's
   errors/warnings to flymake automatically, which is what actually draws the
   squiggly underlines and populates ~M-x flymake-show-buffer-diagnostics~.
   Nothing Rust-specific to configure here.

Completions surface through the *existing* Corfu/Cape stack (see
[[*In-Buffer Completion]]) -- eglot registers a normal
~completion-at-point-function~, the same extension point Cape's sources use,
so Corfu's popup already shows rust-analyzer's completions with no glue code.
~C-c p c~ (from [[*Projects (project.el)]]) runs ~compile~ at the project root,
e.g. typing =cargo build= or =cargo test= there.

*Tree-sitter grammar* is a fourth, easy-to-conflate piece: a small *compiled
C library* that parses Rust source into a syntax tree for ~rust-ts-mode~ to
read (this is what "tree-sitter" refers to -- a parsing library, unrelated to
rust-analyzer). It is not the language server and not bundled with Emacs;
~treesit-install-language-grammar~ clones its (tiny) generated-parser repo and
compiles it once. That one-time build needs Git, a C compiler, and network
access, and installs to =~/.emacs.d/tree-sitter/= -- gitignored, since it is a
compiled, machine-specific binary, not something to carry in the repo.

** Clojure

Same three-layer architecture as [[*Rust]] -- major mode + language server +
flymake -- plus a fourth piece Rust has no analogue for: *CIDER*, a REPL
client. The division of labor between the last two is the thing to hold on
to: ~clojure-lsp~ (spoken to by eglot, exactly like rust-analyzer) knows what
the code *says* -- clj-kondo diagnostics, find-references, rename, all with
no running program -- while CIDER knows what the program is *doing*: it
connects Emacs to a live JVM over the nREPL protocol and evaluates forms
from the buffer into that running process. They are complementary, not
rivals; both run at once.

Differences from the Rust setup, layer by layer:

1. *Major mode* (~clojure-ts-mode~) comes from MELPA rather than being
   bundled -- and it manages its *own* tree-sitter grammar (downloads and
   compiles it on first use; ~clojure-ts-ensure-grammars~ is ~t~ by
   default), so none of the ~treesit-language-source-alist~ /
   ~treesit-install-language-grammar~ dance from the Rust block is needed.
   The one setting worth flagging: ~clojure-ts-toplevel-inside-comment-form~
   makes forms inside a ~(comment ...)~ block count as top-level, which is
   what makes "rich comment" scratchpads evaluable one form at a time.
2. *Language server* (~clojure-lsp~) is an external native binary installed
   per machine via Homebrew (see
   [[file:setup-notes.org::*Clojure (clojure-ts-mode + CIDER + eglot)][setup-notes: Clojure]]),
   wired up with the same one-line ~eglot-ensure~ hook as Rust. Diagnostics
   land in flymake; completions surface through the existing Corfu/Cape
   stack (see [[*In-Buffer Completion]]) with no glue code -- and when a
   CIDER REPL is connected, CIDER's runtime-aware completions join in
   through the same ~completion-at-point~ extension point.
3. *CIDER*: ~C-c C-x j j~ (~cider-jack-in-clj~) in any project with a
   =deps.edn= boots a JVM with an nREPL server injected and connects to it;
   after that, ~C-c C-c~ re-evaluates the top-level form at point into the
   live process (result shown as an inline overlay at point), ~C-c C-e~
   evaluates the form before point, ~C-c C-k~ loads the whole buffer. The
   ~:custom~ settings below tune exactly this inline-results workflow.
4. *Structural editing* (~smartparens~ in strict mode) -- scoped to Clojure
   buffers only, deliberately not enabled for elisp, so it changes no
   existing habits. Strict mode keeps delimiters permanently balanced, and
   editing happens by *expression*: slurp/barf (~C-<right>~ / ~C-<left>~,
   shadowing plain word-motion in these buffers only) grow and shrink the
   current parens, splice (~M-D~) removes the surrounding parens, raise
   (~M-R~) replaces the parent expression with the one at point. Paredit's
   traditional ~M-s~ binding for splice is off-limits here because ~M-s~ is
   the Consult search prefix (see [[*Consult]]).

#+begin_src emacs-lisp

* Encrypted Files (EasyPG)

Emacs's built-in EasyPG Assistant (~epa-file~, enabled by default)
transparently *decrypts* any =.gpg= file when opened and *re-encrypts*
it on save. That -- not any generic save behavior -- is why editing
=~/.authinfo.gpg= (which holds the FreshRSS Fever password, see
[[*Elfeed + FreshRSS (synced RSS)][Elfeed + FreshRSS]]) pops up a recipient prompt: encrypting
needs to know whose key can decrypt the result.

By default it asks on every save. Pointing ~epa-file-encrypt-to~ at my
own key and setting ~epa-file-select-keys~ to nil (which, per its
docstring, means "ask only when no recipient is configured") makes it
encrypt silently to that key. This assumes a personal GPG key for
=hall@absinthe.org= exists --

: gpg --quick-generate-key "Kevin Hall <hall@absinthe.org>"

-- otherwise saving a =.gpg= file fails with "no public key". The
lone ExpressVPN key that ships in the keyring is unrelated and must
not be used as a recipient (its private key isn't ours).

#+begin_src emacs-lisp
(setq epa-file-encrypt-to '("hall@absinthe.org")
      epa-file-select-keys nil)
#+end_src

On macOS, a GUI ~Emacs.app~ or =launchd= daemon has no controlling TTY,
so ~gpg-agent~ cannot pop the default curses ~pinentry~ to ask for the
key passphrase and decryption fails. Loopback pinentry routes the
prompt back through Emacs's own minibuffer instead. It requires
~allow-loopback-pinentry~ in the machine-local =~/.gnupg/gpg-agent.conf=
(not tracked here). Guarded by ~system-type~ so the shared config
leaves the Linux box -- which already has a working graphical pinentry
under X and may not enable loopback in its agent -- untouched.

(when (eq system-type 'darwin)

* Email (notmuch + Fastmail)

Mail lives as a local Maildir at =~/Maildir/fastmail/=, kept in sync with
Fastmail by [[https://isync.sourceforge.io/][isync (~mbsync~)]] and indexed by
[[https://notmuchmail.org/][notmuch]]. notmuch itself neither fetches nor
sends mail -- it only indexes and tags -- so the moving parts are:

- *Fetch*  : ~mbsync -a~ pulls IMAP -> =~/Maildir/fastmail/= (config in =~/.mbsyncrc=).
- *Index*  : ~notmuch new~ indexes the Maildir and applies tags (config in =~/.notmuch-config=).
- *Send*   : ~msmtp~ -- Emacs's built-in ~smtpmail~ can't speak XOAUTH2, which
  Yale requires. Fastmail authenticates with the app password from
  =~/.authinfo.gpg=; Yale (Microsoft 365) with an OAuth2 token from
  =mutt_oauth2.py=. Emacs selects the account by From (config in =~/.msmtprc=).

Everything is portable to Linux: =~/.mbsyncrc= and =~/.msmtprc= use
~$HOME~-relative paths (only =~/.msmtprc='s ~tls_trust_file~ is OS-specific);
=~/.notmuch-config='s absolute ~database.path~ and the machine-local
=~/.authinfo.gpg= differ per machine.

** Secret handling

The Fastmail *app password* (created in Fastmail's web UI, distinct from the
web-login password) must never live in the dotfiles repo. It is stored once
in =~/.authinfo.gpg= (the same encrypted store the FreshRSS Fever password
uses), on two lines -- same app password for both IMAP and SMTP:

: machine imap.fastmail.com login hall@absinthe.org password APP-PASSWORD
: machine smtp.fastmail.com login hall@absinthe.org port 465 password APP-PASSWORD

~mbsync~ reads the IMAP line via its ~PassCmd~; ~msmtp~ reads the SMTP line via
its ~passwordeval~ (the Fastmail account in =~/.msmtprc=).

The ~notmuch~ Emacs package is pulled from ELPA (via ~use-package-always-ensure~)
rather than the copy Homebrew/apt ship with the CLI, so the same config loads
identically on every machine. ~C-c m~ opens the notmuch hello screen.

accounts differ. *Fastmail* does NOT save SMTP-sent mail server-side, so it
gets a local Fcc into =fastmail/Sent= that the next ~mbsync~ uploads. *Yale*
(Office 365) *does* auto-save sent mail into its Exchange =Sent Items=, so its
Fcc is skipped (=nil=) and ~mbsync~ simply pulls the server's copy down -- a
local Fcc there would only duplicate it (and trip the ~notmuch insert~ database
lock, the "Insert failed" prompt, when it races the background ~notmuch new~).
~maildir:synchronize_flags~ in =~/.notmuch-config= means read/flagged state
round-trips: notmuch <-> Maildir flags <-> mbsync <-> server.

** Deleting mail (move to Fastmail Trash)

notmuch has no "delete" -- only tags. ~d~ tags a thread ~deleted~ (which
=search.exclude_tags= hides immediately) and advances. Nothing leaves
Fastmail at that instant. On the next sync the =pre-new= hook physically
moves every ~deleted~ message into the local Trash maildir, and ~mbsync~
relocates it to *Fastmail Trash* -- recoverable there until Fastmail
auto-purges (~30 days). Tagging ~deleted~ does **not** set the Maildir
~T~ flag (verified: notmuch only syncs D/F/P/R/S), so it never triggers an
IMAP expunge on its own; the *move* is what deletes it from the original
folder.

Undo is easy *before* the next sync: ~-deleted~ (or ~notmuch-search-tag~)
puts it right back. After the sync it lives in Fastmail Trash, so recover
it from any Fastmail client. These commands live in a
~with-eval-after-load~ block because they reference ~notmuch-*-mode-map~,
which only exist once notmuch has loaded.

#+begin_src emacs-lisp
(with-eval-after-load 'notmuch
  (defun my/notmuch-search-delete ()
    "Tag thread(s) `deleted' and advance; synced to Fastmail Trash on next poll."
    (interactive)
    (notmuch-search-tag '("+deleted" "-inbox" "-unread"))
    (notmuch-search-next-thread))

  (defun my/notmuch-show-delete ()
    "Tag the current message `deleted' and move to the next thread."
    (interactive)
    (notmuch-show-tag '("+deleted" "-inbox" "-unread"))
    (notmuch-show-next-thread t))

  (define-key notmuch-show-mode-map   (kbd "d") #'my/notmuch-show-delete))

** Auto-fetch every 5 minutes

While Emacs is running, poll Fastmail every 5 minutes in the *background*
(a detached ~notmuch new~, which runs the =pre-new= sync hook) and refresh
any open notmuch buffers when it finishes. Using ~make-process~ instead of
the built-in synchronous ~notmuch-poll~ keeps the ~mbsync~ round-trip off
the main thread, so the UI never freezes mid-sync. A guard skips a new run
while the previous one is still going (notmuch takes a database lock, so
overlapping runs would error), and the timer is cancelled-then-recreated on
every ~C-c r~ so reloads don't stack timers. Polling begins once notmuch is
first loaded in a session (i.e. after my first ~C-c m~).

~G~ (normally the built-in *synchronous* ~notmuch-poll-and-refresh-this-buffer~,
which blocks Emacs for the whole ~mbsync -a~ + index round-trip -- seconds, or
much longer when Office 365 throttles Yale) is rebound in the notmuch buffers to
trigger this *same* background poll. A manual sync then no longer freezes the
UI: ~G~ returns immediately and the open buffers refresh themselves when the
fetch finishes, exactly like the timer. Trade-off: results aren't guaranteed
present the instant ~G~ returns -- new mail appears a moment later on its own.

#+begin_src emacs-lisp
(with-eval-after-load 'notmuch
  (defvar my/notmuch-poll-process nil
    "The most recent background `notmuch new' process, or nil.")

  (defun my/notmuch-poll-async ()
    "Run `notmuch new' in the background, then refresh notmuch buffers."
    (when (or (null my/notmuch-poll-process)
              (not (process-live-p my/notmuch-poll-process)))
      (setq my/notmuch-poll-process
            (make-process
             :name "notmuch-poll" :buffer nil :noquery t
             :command (list notmuch-command "new")
             :sentinel (lambda (_proc event)
                         (when (string-prefix-p "finished" event)
                           (notmuch-refresh-all-buffers)))))))

  (defun my/notmuch-poll-refresh ()
    "Non-blocking replacement for `G' (`notmuch-poll-and-refresh-this-buffer').
Kick off the background `notmuch new' (see `my/notmuch-poll-async')
instead of the built-in synchronous poll, so a manual sync never freezes
the UI.  Open buffers refresh when the fetch finishes; if a poll is
already running, just say so rather than starting a second one."
    (interactive)
    (if (and my/notmuch-poll-process (process-live-p my/notmuch-poll-process))
        (message "notmuch: a background sync is already running…")
      (my/notmuch-poll-async)
      (message "notmuch: syncing mail in the background…")))

  (define-key notmuch-search-mode-map (kbd "G") #'my/notmuch-poll-refresh)
  (define-key notmuch-hello-mode-map  (kbd "G") #'my/notmuch-poll-refresh)
  (define-key notmuch-show-mode-map   (kbd "G") #'my/notmuch-poll-refresh)

  (defvar my/notmuch-poll-timer nil
    "Repeating timer that drives `my/notmuch-poll-async'.")
  (when (timerp my/notmuch-poll-timer) (cancel-timer my/notmuch-poll-timer))
  (setq my/notmuch-poll-timer
        (run-with-timer 300 300 #'my/notmuch-poll-async)))
#+end_src

* Elfeed + FreshRSS (synced RSS)

A feed reader whose read/unread state syncs with the self-hosted
FreshRSS instance (so what I read here is marked read everywhere):
[[https://github.com/skeeto/elfeed][Elfeed]] as the reader and
[[https://github.com/fasheng/elfeed-protocol][elfeed-protocol]] as the
sync layer, talking to FreshRSS over its *Fever API*. FreshRSS is the
source of truth for subscriptions -- feeds are managed there, not in
this file -- and elfeed just mirrors them, pushing read/starred
changes back immediately.

FreshRSS runs in a Proxmox LXC container, reverse-proxied by Caddy at
~https://freshrss.penrhynhalls.net~.  The name resolves to the Caddy
host directly on the LAN, and over Tailscale (via the ~proxmox~ subnet
router) when away -- same URL either way.  Caddy terminates TLS with a
real Let's Encrypt wildcard cert, so plain ~https~ works with no
~--insecure~ curl flags.

** Secret handling

The Fever API password must *not* live in this file (it is tracked in
the dotfiles repo). It is read at load time from ~auth-source~
(=~/.authinfo.gpg=), keyed on the host and user below. Add a line like
this to =~/.authinfo.gpg= (or =~/.authinfo=):

: machine freshrss.penrhynhalls.net login YOUR-FRESHRSS-USER password YOUR-FEVER-API-PASSWORD

If the lookup returns nil (password not yet stored) elfeed simply
won't authenticate until it is added -- nothing here breaks.

** Prerequisites (one-time, in FreshRSS)

1. FreshRSS → Settings → Authentication → tick *Allow API access*.
2. FreshRSS → Settings → Profile → set an *API password* (this is the
   Fever password, distinct from the web-login password) and put it in
   =~/.authinfo.gpg= as above.
3. Import the OPML into FreshRSS if not already, so it holds the feeds.

** Configuration

~my/freshrss-user~ must be set to the FreshRSS account name; it feeds
both the Fever URL and the auth-source lookup. ~C-c e~ opens Elfeed;
inside it, ~G~ fetches/syncs. Categories (the Feedbin folders) come
across as Elfeed tags via ~fetch-category-as-tag~.

Fever's incremental ~G~ only fetches *new* entries and only applies
read-state to what it fetches, so articles read on another device keep
a stale ~unread~ tag here (and ~elfeed-protocol-fever-reinit~ doesn't
fix it). ~my/elfeed-freshrss-clear-read~ closes that gap: it pulls the
server's live ~unread_item_ids~ set and mirrors it onto the local
entries, so reading elsewhere finally clears here.

This runs *automatically after every sync*:
~my/elfeed-freshrss-reconcile-after-sync~ is on ~elfeed-update-hook~
(debounced), so a plain ~G~ now both fetches new articles and clears
what I read on another device. It is also still bound to ~C-c E~ for
the one case the hook misses -- when the server's unread set is empty,
~G~ fetches nothing and the update hook never fires, so a manual ~C-c
E~ is the way to clear the last few.

That mirroring must not echo back to the server, and enforcing this
takes explicit care. ~elfeed-tag-1~/~elfeed-untag-1~ used to be the
hook-free tagging primitives, but elfeed 4.0.0 turned them into
obsolete aliases for ~elfeed-tag~/~elfeed-untag~, which *do* run
~elfeed-tag-hook~/~elfeed-untag-hook~ -- where elfeed-protocol installs
its write-back handlers. The reconcile therefore binds both hooks to
nil for the duration of the walk. Without that it crashes with
"wrong-type-argument stringp nil": any entry whose proto-id is not in
the current ~elfeed-feeds~ (stale ones survive a change of feed URL --
this database still holds entries from an older ~fever+http://...~ IP
address) resolves to a nil host-url, which ~elfeed-protocol-meta-user~
then hands to ~split-string~.

Those stale entries are not just a crash trigger for the reconcile --
they show up as permanent *duplicate rows* (one live, one dead) and the
dead copy errors on open. ~my/elfeed-purge-dead-protocol-entries~
(=M-x=) clears them out for good: it deletes every entry and feed whose
~:protocol-id~ is not among the current ~elfeed-feeds~, after showing a
count and asking. Run it once after a server-URL change.

The search buffer's default line layout caps the title at
~elfeed-search-title-max-width~ (70) and left-packs the feed name after
it, wasting the right half of a wide frame. ~my/elfeed-search-print-entry~
replaces ~elfeed-search-print-entry-function~ to instead right-align the
feed+tags block to the window edge and let the title fill everything in
between -- so widening the frame widens the title, on one line. It keeps
the default faces and the ~kbd-help~ tooltip; only the geometry changes.

#+begin_src emacs-lisp
;; defconst, not defvar: these are edited in this file and must update
;; on `C-c r'.  `defvar' only assigns when the symbol is unbound, so once
;; the daemon has a value it ignores later edits until a full restart;
;; `defconst' reassigns on every load.
(defconst my/freshrss-host "freshrss.penrhynhalls.net"
  "Hostname of the FreshRSS instance, reverse-proxied by Caddy.
Resolves to the Caddy host on the LAN, and over Tailscale when away.")

(defconst my/freshrss-user "hall"
  "FreshRSS account name, used for the Fever URL and auth-source lookup.")

(defvar my/elfeed-known-categories (make-hash-table :test 'eq)
  "FreshRSS category tags (interned symbols) currently known.
Populated by `my/elfeed-freshrss-refresh-categories'.
`my/elfeed-search-print-entry' consults this to decide which tags get a
category color -- `unread' and any other non-category tag are left with
the default face.  A plain `defvar' (not `defconst'): this is accumulated
state refreshed by a sync, not a config value that should reset on `C-c

(defun my/elfeed-category-color (name)
  "Return a stable hex color for category NAME (a string or symbol).
Hashes NAME to a hue (0-359 degrees) with `sxhash-equal' -- deterministic,
so the same category name always gets the same color across restarts and
machines, with nothing to store or hand-pick as categories are added.
Saturation and lightness are fixed so every generated color stays legible
against both light and dark themes; only the hue varies."
  (require 'color)
  (let* ((name (if (symbolp name) (symbol-name name) name))
         (hue (/ (mod (abs (sxhash-equal name)) 360) 360.0)))
    (apply #'color-rgb-to-hex (append (color-hsl-to-rgb hue 0.55 0.65) '(2)))))

(defun my/elfeed-freshrss-clear-read ()
  "Mirror FreshRSS read/unread state onto already-downloaded Elfeed entries.
elfeed-protocol's Fever sync only applies read-state to entries it
*fetches*, and `G' fetches only new ids -- so articles read on
another device keep a stale `unread' tag here, and
`elfeed-protocol-fever-reinit' does not fix it either.

This fetches the Fever `unread_item_ids' set directly and, for
every local entry carrying a Fever id, adds or removes the
`unread' tag to match the server -- locally only, so nothing is
pushed back.  The Fever api_key is md5(user:password); the
password comes from auth-source, never from this file.

Local-only is enforced by binding `elfeed-tag-hook' and
`elfeed-untag-hook' to nil around the walk, NOT by the choice of
tagging function: `elfeed-tag-1'/`elfeed-untag-1' were the
hook-free primitives when this was written, but elfeed 4.0.0 made
them obsolete aliases for `elfeed-tag'/`elfeed-untag', which do
run the hooks."
  (interactive)
  (let* ((host my/freshrss-host) (user my/freshrss-user)
         (pw (auth-source-pick-first-password :host host :user user))
         (key (md5 (concat user ":" pw)))
         (url (format "https://%s/api/fever.php?api&unread_item_ids" host))
         (url-request-method "POST")
         (url-request-extra-headers
          '(("Content-Type" . "application/x-www-form-urlencoded")))
         (url-request-data (concat "api_key=" key))
         (unread-set (make-hash-table :test 'eql)))
    (with-current-buffer (url-retrieve-synchronously url t t 30)
      (goto-char (point-min))
      (re-search-forward "\n\n" nil t)
      (let* ((json (json-parse-buffer :object-type 'alist))
             (ids (alist-get 'unread_item_ids json)))
        (unless (eql 1 (alist-get 'auth json))
          (user-error "FreshRSS Fever auth failed"))
        (dolist (id (split-string (or ids "") "," t))
          (puthash (string-to-number id) t unread-set))))
    (let ((cleared 0) (marked 0)
          ;; Keep the walk local.  elfeed-protocol hangs
          ;; `elfeed-protocol-on-tag-remove' on `elfeed-untag-hook', so
          ;; each untag here would POST "mark as read" back to FreshRSS --
          ;; pointless (we are mirroring the server's own state) and
          ;; actively fatal: entries whose proto-id is no longer in
          ;; `elfeed-feeds' (e.g. left over from an earlier feed URL)
          ;; resolve to a nil host-url, and `elfeed-protocol-meta-user'
          ;; then dies in `split-string' with "stringp nil".
          (elfeed-tag-hook nil)
          (elfeed-untag-hook nil))
      (with-elfeed-db-visit (entry _feed)
        (let ((id (elfeed-meta entry :id)))
          (when id
            (if (gethash id unread-set)
                (unless (elfeed-tagged-p 'unread entry)
                  (elfeed-tag entry 'unread) (setq marked (1+ marked)))
              (when (elfeed-tagged-p 'unread entry)
                (elfeed-untag entry 'unread) (setq cleared (1+ cleared)))))))
      (elfeed-db-save)
      (when (get-buffer "*elfeed-search*")
        (with-current-buffer "*elfeed-search*" (elfeed-search-update :force)))
      (message "FreshRSS reconcile: cleared %d read, marked %d unread; %d unread on server"
               cleared marked (hash-table-count unread-set)))))

;; Run the read-state reconcile automatically after every sync.  A plain
;; `G' (unread-only Fever sync) only *imports* the server's currently-unread
;; ids; it never clears the `unread' tag from entries read on another device
;; -- those just drop out of the fetched set and elfeed never revisits them.
;; So without this, reading on the phone never propagates here.
;; `elfeed-update-hook' fires from inside elfeed-curl's process sentinel and
;; can fire several times per `G' (once per id chunk), so debounce onto a
;; short timer: the fires collapse into a single reconcile that runs just
;; after the sync's own DB writes settle, off the sentinel.  Manual `C-c E'
;; still works for the rare case where the server's unread set is empty (then
;; `G' fetches nothing and this hook never fires).
(defvar my/elfeed-reconcile-timer nil
  "Debounce timer coalescing post-sync `my/elfeed-freshrss-clear-read' runs.")

(defun my/elfeed-freshrss-reconcile-after-sync (&rest _)
  "Schedule one read-state reconcile shortly after a sync settles.
Added to `elfeed-update-hook'; debounced via `my/elfeed-reconcile-timer'
so the several per-sync hook fires trigger only a single reconcile."
  (when (timerp my/elfeed-reconcile-timer)
    (cancel-timer my/elfeed-reconcile-timer))
  (setq my/elfeed-reconcile-timer
        (run-at-time 2 nil #'my/elfeed-freshrss-clear-read)))

(add-hook 'elfeed-update-hook #'my/elfeed-freshrss-reconcile-after-sync)

(defun my/elfeed-purge-dead-protocol-entries ()
  "Delete Elfeed entries and feeds orphaned by a changed protocol URL.
elfeed-protocol stamps every entry with a `:protocol-id' naming the
server it came from (e.g. `fever+https://user@host').  Change that URL
-- a new hostname, or http->https -- and the entries and feed objects
fetched under the *old* proto-id linger in the database forever: they
render as duplicate rows, and opening one dies in
`elfeed-protocol-meta-user' because the stale proto-id no longer maps
to a configured host.  (This database once held ~123 entries under an
old `fever+http://hall@100.121.73.82' Tailscale-IP address.)

This removes every entry and every feed whose proto-id is not among the
currently-configured `elfeed-feeds'.  It reports the counts and asks
before deleting.  Run it after changing the FreshRSS URL; it is a
harmless no-op when nothing is stale.  Only protocol feeds (a `scheme+'
url) are ever considered, so a plain-RSS feed is never touched."
  (interactive)
  (elfeed-db-ensure)
  (let* ((proto-of (lambda (url) (car (split-string url "::"))))
         (live (delete-dups
                (mapcar (lambda (f) (funcall proto-of (if (listp f) (car f) f)))
                        elfeed-feeds)))
         (dead-entries '()) (dead-unread 0) (dead-feeds '()))
    (maphash (lambda (_id e)
               (let ((pid (elfeed-meta e :protocol-id)))
                 (when (and pid (not (member pid live)))
                   (push e dead-entries)
                   (when (memq 'unread (elfeed-entry-tags e))
                     (setq dead-unread (1+ dead-unread))))))
             elfeed-db-entries)
    (maphash (lambda (url _f)
               (when (and (string-match-p "\\`[a-z]+\\+" url)
                          (not (member (funcall proto-of url) live)))
                 (push url dead-feeds)))
             elfeed-db-feeds)
    (if (and (null dead-entries) (null dead-feeds))
        (message "Elfeed: no dead-protocol entries or feeds; nothing to purge")
      (when (yes-or-no-p
             (format "Delete %d dead entries (%d unread) and %d dead feeds? "
                     (length dead-entries) dead-unread (length dead-feeds)))
        (elfeed-db-delete dead-entries)
        (dolist (url dead-feeds) (remhash url elfeed-db-feeds))
        (elfeed-db-save)
        (when (get-buffer "*elfeed-search*")
          (with-current-buffer "*elfeed-search*" (elfeed-search-update :force)))
        (message "Elfeed: purged %d entries and %d dead feeds"
                 (length dead-entries) (length dead-feeds))))))

(defun my/elfeed-freshrss-refresh-categories ()
  "Retag already-downloaded entries with their *current* FreshRSS category.
elfeed-protocol computes an entry's category tag only once, at the moment
it is first inserted into the database (see
`elfeed-protocol-fever--parse-entries' in elfeed-protocol-fever.el): unlike
the `unread'/starred tags, which it force-overrides on every sync, it never
revisits an existing entry's category. So re-categorizing a feed in
FreshRSS has no effect on articles already synced here -- only new articles
fetched afterward would get it right -- and there is no
`elfeed-protocol-fever-reinit'-style command that fixes it either, since
matching entries are still treated as already-existing, not new.

This fetches FreshRSS's live feed -> category mapping directly (the same
`?api&groups' endpoint elfeed-protocol-fever itself uses) and, for every
local entry, swaps out whichever known category tag it currently carries
for the correct one -- locally only, same pattern as
`my/elfeed-freshrss-clear-read'. Runs automatically after every sync via
`elfeed-update-hook' (after `my/elfeed-dedupe-by-title', so it also cleans
up any category drift that merge step can reintroduce -- see the comment
on its `add-hook' call), and can still be run by hand with `C-c c'. Forces
a fresh auth-source decrypt first
(see the `:password' lambda above) rather than risking a stale cached
password in a long-running session.

Runs automatically and unsupervised (no human watching for a failure to
retry), so any error here -- a network hiccup, a timed-out request, an
unexpected response -- is caught and logged to `*elfeed-log*'
(`M-x elfeed-log-show') instead of propagating as an unhandled error.  An
unhandled error inside a timer callback (which is what runs this after a
deferred hook fire) is exactly what produces an auto-popping, easy-to-miss
`*Backtrace*' window -- this replaces that with the same quiet failure
handling elfeed itself uses for its own Fever errors."
  (interactive)
  (condition-case err
      (let* ((host my/freshrss-host) (user my/freshrss-user)
             (pw (progn (auth-source-forget-all-cached)
                        (auth-source-pick-first-password :host host :user user)))
             (key (md5 (concat user ":" pw)))
             (url (format "https://%s/api/fever.php?api&groups" host))
             (url-request-method "POST")
             (url-request-extra-headers
              '(("Content-Type" . "application/x-www-form-urlencoded")))
             (url-request-data (concat "api_key=" key))
             ;; Fever feed-id -> category name.
             (feed-category (make-hash-table :test 'eql))
             (response-buffer (url-retrieve-synchronously url t t 30)))
        (unless response-buffer
          (error "No response from %s (network failure or timeout)" host))
        ;; Every category name currently in use, as interned tag symbols --
        ;; anything in this set on an entry is a category tag eligible for
        ;; replacement (and for a color, see `my/elfeed-category-color');
        ;; anything else (unread, starred, user tags) is left alone.  This is
        ;; the persistent, shared table (not a local one) so
        ;; `my/elfeed-search-print-entry' can also consult it; clear it first
        ;; so a category removed server-side stops being treated as one.
        (clrhash my/elfeed-known-categories)
        (with-current-buffer response-buffer
          (goto-char (point-min))
          (unless (re-search-forward "\n\n" nil t)
            (error "Malformed HTTP response from %s" host))
          (let* ((json (json-parse-buffer :object-type 'alist :array-type 'list))
                 (groups (alist-get 'groups json))
                 (feeds_groups (alist-get 'feeds_groups json))
                 (group-title (make-hash-table :test 'eql)))
            (unless (eql 1 (alist-get 'auth json))
              (error "FreshRSS Fever auth failed"))
            (dolist (g groups)
              (let ((title (alist-get 'title g)))
                (puthash (alist-get 'id g) title group-title)
                (puthash (intern title) t my/elfeed-known-categories)))
            (dolist (fg feeds_groups)
              (let ((title (gethash (alist-get 'group_id fg) group-title)))
                (when title
                  (dolist (fid (split-string (alist-get 'feed_ids fg) "," t))
                    (puthash (string-to-number fid) title feed-category)))))))
        (let ((changed 0)
              ;; Local-only, same reasoning as `my/elfeed-freshrss-clear-read':
              ;; category tags aren't unread/star, so the pre-tag/pre-untag
              ;; hooks would no-op regardless, but binding nil skips the
              ;; dispatch entirely for this bulk walk.
              (elfeed-tag-hook nil)
              (elfeed-untag-hook nil))
          (with-elfeed-db-visit (entry _feed)
            (let* ((feed-id (elfeed-meta entry :feed-id))
                   (correct (and feed-id (gethash feed-id feed-category)))
                   (correct-tag (and correct (intern correct)))
                   touched)
              (when correct-tag
                ;; Always strip any *other* known-category tag, even if
                ;; correct-tag is already present -- e.g. after
                ;; `my/elfeed-dedupe-by-title' merges a stale-tagged duplicate
                ;; into a survivor that already has the right tag, both can
                ;; end up set at once.  Skipping this loop just because the
                ;; correct tag is already there (the first version of this
                ;; function did) left that combination un-healed forever.
                (dolist (tag (elfeed-entry-tags entry))
                  (when (and (not (eq tag correct-tag)) (gethash tag my/elfeed-known-categories))
                    (elfeed-untag entry tag)
                    (setq touched t)))
                (unless (elfeed-tagged-p correct-tag entry)
                  (elfeed-tag entry correct-tag)
                  (setq touched t))
                (when touched (setq changed (1+ changed))))))
          (elfeed-db-save)
          (when (get-buffer "*elfeed-search*")
            (with-current-buffer "*elfeed-search*" (elfeed-search-update :force)))
          (message "FreshRSS categories: retagged %d entries" changed)))
    (error
     (elfeed-log 'error "my/elfeed-freshrss-refresh-categories: %s" (error-message-string err))
     (when (called-interactively-p 'any)
       (message "FreshRSS categories: failed (%s) -- see *elfeed-log*"
                (error-message-string err))))))

;; Run after `my/elfeed-dedupe-by-title' on every sync (depth 90, so it always
;; lands after that hook regardless of load order), cleaning up any category
;; drift the merge step reintroduces, and picking up FreshRSS re-categorizing
;; on its own without a manual `C-c c'.
;;
;; `elfeed-update-hook' fires from inside elfeed-curl's process sentinel --
;; an async callback.  Unlike `my/elfeed-dedupe-by-title' (pure local
;; database work), this function makes a *blocking* network call
;; (`url-retrieve-synchronously'), and nesting that directly inside a
;; process-sentinel callback is a known-bad pattern: an error there
;; doesn't just print a message, it pops a `*Backtrace*' window (Emacs's
;; standard handling for unhandled errors in timers/sentinels) that stays
;; open until closed by hand.  `run-at-time 0 nil ...' defers the actual
;; call to the next event-loop tick, off the sentinel's call stack
;; entirely, while still running immediately after the sync completes.
(add-hook 'elfeed-update-hook
          (lambda (&rest _) (run-at-time 0 nil #'my/elfeed-freshrss-refresh-categories))
          90)

** Duplicate entries from unstable guids (e.g. Stratechery)

Elfeed dedupes articles by each item's ~<guid>~ (falling back to its link),
so a feed whose guid isn't stable across fetches produces a fresh "new"
Elfeed entry for the *same* article every time. Stratechery hits this hard:
it's proxied through =passport.online= (a subscription-auth gateway) whose
feed embeds a short-lived, periodically-reissued access token *directly in
the article link*, which is also what ends up as the guid. Confirmed by
comparing two "duplicate" entries for the same article: identical title and
underlying =stratechery.com/?p=19180= URL, but the token's issued-at claim
was ~25 hours apart -- so the guid, and therefore Elfeed's dedup key,
genuinely changed between two ordinary polls of the exact same article.
Nothing on this end (Elfeed, elfeed-protocol, or FreshRSS config) causes or
can prevent this; it is the upstream feed's own guid hygiene.

~my/elfeed-dedupe-by-title~ mops this up after the fact: group entries by
(feed . title), and where a group has more than one, keep only the most
recently dated copy (its access-token link is the one still valid) and merge
the others' tags onto it first, so an already-read older copy doesn't
resurrect that article as unread. It runs automatically after every sync via
~elfeed-update-hook~, and can also be run by hand.

#+begin_src emacs-lisp
(defun my/elfeed-dedupe-by-title (&optional _url)
  "Merge duplicate Elfeed entries sharing a feed and title, keeping the newest.
Also runs from `elfeed-update-hook', which passes the just-synced feed URL
as _URL; unused here since the whole database is rescanned regardless."
  (interactive)
  (let ((groups (make-hash-table :test 'equal))
        (removed 0))
    ;; Bucket every entry by (feed . title) -- these are the "same article,
    ;; different guid" groups we're hunting for.
    (with-elfeed-db-visit (entry feed)
      (push entry (gethash (cons (elfeed-feed-id feed) (elfeed-entry-title entry))
                            groups)))
    (maphash
     (lambda (_key entries)
       (when (> (length entries) 1)
         (let* ((newest-first (sort entries
                                    (lambda (a b) (> (elfeed-entry-date a)
                                                      (elfeed-entry-date b)))))
                (keep (car newest-first))
                (dupes (cdr newest-first)))
           ;; Carry over tags (e.g. `unread'/`starred') from the copies being
           ;; removed, so deleting them can't silently lose read-state.
           (dolist (dupe dupes)
             (apply #'elfeed-tag keep (elfeed-entry-tags dupe)))
           (elfeed-db-delete dupes)
           (setq removed (+ removed (length dupes))))))
     groups)
    (elfeed-db-save)
    (when (get-buffer "*elfeed-search*")
      (with-current-buffer "*elfeed-search*" (elfeed-search-update :force)))
    (when (called-interactively-p 'any)
      (message "Elfeed: merged %d duplicate entr%s" removed (if (= removed 1) "y" "ies")))
    removed))

(add-hook 'elfeed-update-hook #'my/elfeed-dedupe-by-title)
#+end_src

* Web Browsing (eww)

~eww~ renders HTML with ~shr~, no JavaScript. It will never match a real
browser, but a few ~shr~ defaults make ordinary pages far more readable:

- ~shr-use-colors nil~ -- the biggest win. By default ~shr~ paints each page's
  *own* colours, which often clash with the theme (washed-out low-contrast
  text). Off, pages use my theme's faces, so contrast is consistent everywhere
  ~shr~ renders (eww, HTML mail in notmuch, Elfeed article bodies).
- ~shr-max-width 90~ (from 120) -- wrap body text to a readable column instead
  of stretching across the whole frame.
- ~shr-max-image-proportion 0.6~ (from 0.9) -- keep hero images and publisher
  logos from dominating the viewport.

Per-page keys still apply: ~R~ (~eww-readable~) re-renders just the extracted
article, and ~M-I~ (~eww-toggle-images~) hides images for a text-only read.
~eww-readable-urls~ takes a list of URL regexps to auto-apply the readable view
on sites I read often -- left empty here to fill in per taste. (JavaScript
aggregators like news.google.com only expose fallback markup and stay poor;
for news *feeds*, Elfeed above is the better tool.)

#+begin_src emacs-lisp
(use-package shr

  :config
  (setq shr-use-colors nil
        shr-max-width 90
        shr-max-image-proportion 0.6))

(use-package eww
  :ensure nil

** Nicer rendering, readable Org, and a real browser

Three upgrades layered on top of eww:

- *shrface* re-skins ~shr~'s output with Org-like headings, real paragraph
  typography, bullet lists, and ~TAB~ folding + ~imenu~ navigation -- a big
  visual jump for eww, Elfeed article bodies, and HTML mail (anything ~shr~
  renders). ~shrface-basic~ installs its handlers into
  ~shr-external-rendering-functions~; ~shrface-mode~ (added to
  ~eww-after-render-hook~) adds the outline/navigation.
- *org-web-tools* fetches a URL, runs readability, and converts the article
  into a clean *Org buffer* (headings, links, no chrome) -- the best
  distraction-free read of a content-in-HTML page (needs =pandoc=). Its
  ~org-web-tools-read-url-as-org~ takes the URL *silently from the
  clipboard/kill-ring* and never prompts (so: eww ~w~ to copy the page URL,
  then run it). ~C-c u~ (~my/read-url-as-org~) is a wrapper that always
  prompts, with any copied URL pre-filled as the default.
- *xwidget-webkit* is a real embedded WebKit engine (this build is
  ~--with-xwidgets~) for the JavaScript-heavy pages ~eww~ can't render at all.
  In eww, ~W~ reopens the current page in WebKit; ~M-x
  xwidget-webkit-browse-url~ opens any URL directly. (Paywalls/logins still
  apply -- it behaves like a browser.)

#+begin_src emacs-lisp
(use-package shrface
  :after shr
  :config
  (shrface-basic)
  (shrface-trial)
  (setq shrface-href-versatile t)
  (add-hook 'eww-after-render-hook #'shrface-mode))

(use-package org-web-tools
  :commands (org-web-tools-read-url-as-org org-web-tools-insert-link-for-url))

;; `org-web-tools-read-url-as-org' takes the URL silently from the
;; clipboard/kill-ring and never prompts.  This wrapper always asks, with any
;; copied URL pre-filled as the default -- so `C-c u' works whether or not I
;; copied a link first.
(defun my/read-url-as-org (url)
  "Read URL as a clean Org buffer, prompting (default: clipboard/kill-ring URL)."
  (interactive (progn (require 'org-web-tools)
                      (list (read-string "URL: " (org-web-tools--get-first-url)))))
  (org-web-tools-read-url-as-org url))
(global-set-key (kbd "C-c u") #'my/read-url-as-org)

;; A real WebKit view for pages eww can't handle (needs --with-xwidgets).
(defun my/eww-open-in-xwidget ()
  "Reopen the current eww page in an embedded WebKit (xwidget) view."
  (interactive)
  (let ((url (eww-current-url)))
    (unless url (user-error "No current eww URL"))
    (xwidget-webkit-browse-url url)))
(with-eval-after-load 'eww
  (define-key eww-mode-map (kbd "W") #'my/eww-open-in-xwidget))

** External calendars (read-only: Outlook + iCloud)

Org's agenda only reads local Org files, so the two calendars are mirrored in
and converted to Org:

- [[https://vdirsyncer.pimutils.org/][vdirsyncer]] fetches each calendar into a single =.ics= file. *iCloud* uses
  CalDAV (=caldav.icloud.com= + an Apple *app-specific password* kept in
  =~/.authinfo.gpg=, read by a helper). *Yale Outlook* uses a published-ICS URL
  (from Outlook web) as a read-only ~http~ source, since Microsoft removed
  CalDAV from Office 365. The Yale URL is a capability token, so it lives only
  in the machine-local vdirsyncer =config=, never in the repo.
- =ical2orgpy= converts each synced =.ics= into an =.org= file under
  =~/org/calendars/= with a readable =#+CATEGORY=, which the agenda picks up.
- =~/.config/vdirsyncer/sync-calendars.sh= runs the sync + conversion; the Emacs
  timer below (~my/calendar-sync~) fires it every 30 min while Emacs is open --
  like the notmuch poll -- and refreshes an open agenda. The Org files are
  generated, never hand-edited.

The vdirsyncer =config=, the =icloud-pw.sh= helper, and =sync-calendars.sh=
come from =stow calendars=. Only two files are machine-local and gitignored:
=~/.config/vdirsyncer/yale-ics-url= (the Yale capability token, read by the
config via ~url.fetch~) and =icloud-names.tsv= (personal calendar names). The
iCloud app password is in =~/.authinfo.gpg=; nothing is stored plaintext.
Rebuild steps are in =setup-notes.org=.

#+begin_src emacs-lisp
(defvar my/calendar-sync-script "~/.config/vdirsyncer/sync-calendars.sh"
  "Script that syncs external calendars and regenerates ~/org/calendars/*.org.")

(defun my/calendar-sync ()
  "Refresh the external-calendar mirrors in the background, then rebuild an
open agenda so new events appear.  The sync script runs detached, so Emacs
never blocks on the network."
  (interactive)
  (let ((script (expand-file-name my/calendar-sync-script)))
    (when (file-exists-p script)
      (make-process
       :name "calendar-sync" :buffer nil :noquery t
       :command (list script)
       :sentinel
       (lambda (_proc event)
         (when (string-prefix-p "finished" event)
           ;; Revert any (unmodified) calendar buffers, then redo an open agenda.
           (dolist (b (buffer-list))
             (when (and (buffer-file-name b)
                        (string-prefix-p (expand-file-name "~/org/calendars/")
                                         (buffer-file-name b))
                        (not (buffer-modified-p b)))
               (with-current-buffer b (revert-buffer t t t))))
           (let ((buf (get-buffer "*Org Agenda*")))
             (when (buffer-live-p buf)
               (with-current-buffer buf
                 (when (derived-mode-p 'org-agenda-mode)
                   (org-agenda-redo t)))))))))))

(defvar my/calendar-sync-timer nil
  "Repeating timer that drives `my/calendar-sync'.")
(when (timerp my/calendar-sync-timer) (cancel-timer my/calendar-sync-timer))
(setq my/calendar-sync-timer (run-with-timer 30 1800 #'my/calendar-sync))
#+end_src
