* Introduction

This is a literate Emacs configuration. Everything Emacs actually
loads is generated from the ~emacs-lisp~ source blocks in this file:
~init.el~ tangles this file into ~config.el~ and loads that on every
startup (only re-tangling when this file is newer than ~config.el~).

To change my configuration, edit *this file*, not ~init.el~ or
~config.el~ — the latter is generated and any hand edits to it will
be silently overwritten on the next startup.

* Preamble

~org-babel-load-file~ tangles every block below into ~config.el~
with a leading ~:comments link~ line (per the file-wide
~header-args~ above), so the *first* line of ~config.el~ is normally
a comment pointing back to this file's headings, not a
~lexical-binding~ cookie. Emacs only honors that cookie on the
file's literal first line, and a trailing "Local Variables" footer
turns out to be unreliable for it too (Emacs warns that lexical-
binding set only at the end of a file can't be trusted, since
loading may already be underway by the time it's read). So this
block overrides ~:comments~ to ~no~, making it tangle as a bare first
line, matching every hand-written file in this directory and
avoiding the native compiler's dynamic-scope warning on ~config.el~.

#+begin_src emacs-lisp :comments no
;;; config.el --- generated from config.org -*- lexical-binding: t; -*-
#+end_src

* Package Management

We use the built-in =package.el= with MELPA added as a package
archive, plus =use-package= to declare and configure each package in
one place. =use-package-always-ensure= means every =use-package= form
below will auto-install its package if it isn't already present.

#+begin_src emacs-lisp
  (require 'package)
  (add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/") t)
  (package-initialize)
  (unless package-archive-contents
    (package-refresh-contents))
  (setq use-package-always-ensure t)
#+end_src

** Inherit the shell PATH (macOS)

A GUI ~Emacs.app~ launched from Finder/Dock/Spotlight -- or an Emacs
daemon started by =launchd= -- does *not* inherit the login shell's
=PATH=. It gets a bare =/usr/bin:/bin:/usr/sbin:/sbin=, which omits
Homebrew's =/opt/homebrew/bin=. That makes ~executable-find~ miss
~gpg~, so EasyPG's ~epg-find-configuration~ returns nil and opening any
=.gpg= file (e.g. =~/.authinfo.gpg=, which holds the FreshRSS Fever
password) fails with *"no usable configuration, OpenPGP"* -- even
though ~gpg~ works fine from a terminal. On Linux this never happens
because ~gpg~ lives in =/usr/bin=, which is always on =PATH=.

[[https://github.com/purcell/exec-path-from-shell][exec-path-from-shell]] copies the real shell =PATH= (and =exec-path=)
into Emacs at startup, fixing this for ~gpg~ and any other Homebrew
CLI tool. Guarded by ~system-type~ (not ~window-system~, which is nil
in a daemon frame) and wrapped in ~when~ so the shared =config.org=
never installs or runs it on the Linux box.

#+begin_src emacs-lisp
(when (eq system-type 'darwin)
  (use-package exec-path-from-shell
    :config
    (exec-path-from-shell-initialize)))
#+end_src

* Basic UI and Startup Behavior

Trim the startup screen and chrome, and give new frames a bit more
room. Frame dimensions are per-machine, same reasoning as the font
height below: the Linux box keeps its original 45-line-tall default
(width unspecified), ~KevinsMacStudio~ opens at 100x60 characters, and
this machine opens at 115x52.

~use-short-answers~ (Emacs 28+) makes every ~yes-or-no-p~ prompt
accept a single ~y~/~n~ keypress instead of a typed-out "yes"/"no"
followed by ~RET~ -- the modern replacement for the old
~(defalias 'yes-or-no-p 'y-or-n-p)~ trick.

(setq inhibit-startup-message t)
(menu-bar-mode -1)
(tool-bar-mode -1)
(setq visible-bell t)
(setq use-short-answers t)
(cond ((string-prefix-p "KevinsMacStudio" (system-name))
       (add-to-list 'default-frame-alist '(width . 100))
       (add-to-list 'default-frame-alist '(height . 60)))
      ((string-prefix-p "MWC9JXJTGDXD" (system-name))
       (add-to-list 'default-frame-alist '(width . 115))
       (add-to-list 'default-frame-alist '(height . 52)))
      (t
       (add-to-list 'default-frame-alist '(height . 45))))
#+end_src

** Smooth scrolling through tall images

Line-based scrolling treats an image as a single tall "line": if it is
taller than the window, ~scroll-up-command~ cannot stop partway into it
and instead jumps clear past it to the next line -- so an article with a
big image (e.g. an Elfeed entry) skips the image entirely. ~pixel-scroll-
precision-mode~ scrolls by pixels instead, gliding smoothly through
over-tall images. It rebinds the mouse wheel / trackpad and
~PageUp~/~PageDown~; the keyboard ~SPC~ paging in ~elfeed-show~ is remapped
separately in the [[*Elfeed + FreshRSS (synced RSS)][Elfeed]] block.

#+begin_src emacs-lisp
(pixel-scroll-precision-mode 1)
#+end_src

** Fonts

Try SF Mono first, then Menlo (macOS's own default monospace,
always present), then JetBrainsMono Nerd Font (Omarchy's default
mono on ~framework~), then whatever Emacs already resolves to. SF
Mono is bundled *inside* apps like Xcode and Terminal but isn't
registered as a system font other apps can look up by name unless
it's separately installed (Apple distributes it standalone at
[[https://developer.apple.com/fonts/]]) -- so on a fresh machine
~(member "SF Mono" (font-family-list))~ comes back nil and this
falls through to the next candidate.

Critically, the height is set unconditionally, outside any font-
family check -- previously it was set only inside the ~when~ guard
above, so on a machine without SF Mono registered, the size never
applied either. Height is per-machine: this config is shared
between ~framework~ (130 / 13pt) and ~KevinsMacStudio~, whose
display needs 180 / 18pt to look the same size. ~system-name~
distinguishes them so one ~config.org~ can serve both without
editing this on every pull.

The same function also sets the proportional ~variable-pitch~ face --
used for prose body text in ~prose-mode~ (see [[*Prose Writing][Prose Writing]]) -- to
Apple's San Francisco text cut when installed. Both machines have SF
Pro, so prose looks consistent across them, and it degrades
gracefully to the generic sans elsewhere.

Daemon sessions can't do this at init time: the daemon starts with
no display, so ~font-family-list~ is empty and the default face's
family is meaningless -- baking those in is what garbled fonts in
~emacsclient~ frames. Under ~daemonp~, defer to
~server-after-make-frame-hook~, which runs once a real frame
exists (re-running per frame is idempotent and cheap).

#+begin_src emacs-lisp
(defun my/apply-font-settings ()
  "Set the default and variable-pitch face families for this machine.
Must run with a graphical frame live: in a daemon session
`font-family-list' is empty until a frame connects to a display.

The `variable-pitch' face is the proportional face `mixed-pitch'
switches prose body text to (see `prose-mode'); we point it at
Apple's San Francisco text face when present. \"SF Pro Text\" is the
body-optimized cut (as opposed to \"SF Pro Display\" for headline
sizes); the umbrella \"SF Pro\" name does not resolve, so the specific
cuts are named. When neither is installed the face is left alone,
falling back to its default \"Sans Serif\"."
  (let ((mono-font (seq-find (lambda (f) (member f (font-family-list)))
                             '("SF Mono" "Menlo" "JetBrainsMono Nerd Font")))
        (prose-font (seq-find (lambda (f) (member f (font-family-list)))
                              '("SF Pro Text" "SF Pro Display"))))
    (set-face-attribute
     'default nil
     :family (or mono-font (face-attribute 'default :family))
     ;; Per-machine default height (variable-pitch inherits this).
     :height (cond ((string-prefix-p "KevinsMacStudio" (system-name)) 180)
                   ((string-prefix-p "MWC9JXJTGDXD" (system-name)) 170)
                   (t 130)))
    (when prose-font
      ;; Family only: leaving :height unspecified lets variable-pitch
      ;; inherit the per-machine default height above, so `prose-mode's
      ;; text-scale bump still applies on top.
      (set-face-attribute 'variable-pitch nil :family prose-font))))

(if (daemonp)
    (add-hook 'server-after-make-frame-hook #'my/apply-font-settings)
  (my/apply-font-settings))
#+end_src

* Themes

Doom Themes provides the color theme plus small integrations (a
flashing mode-line on errors, and better =org-mode= fontification).
~C-c t~ toggles between ~doom-tomorrow-night~ (dark, the default) and
~doom-tomorrow-day~ (light), alternating from whichever theme is
currently active.

Both themes ship *inside* the ~doom-themes~ package -- there is no
separate =doom-tomorrow-night= package on MELPA, so trying to
~:ensure~ one fails with "package is unavailable". The theme is simply
~load-theme~'d below; ~custom-safe-themes t~ marks every theme trusted
so ~load-theme~ never stops to prompt.

#+begin_src emacs-lisp
(setq custom-safe-themes t)

(use-package doom-themes
  :ensure t
  :config
  ;; Global settings (optional).
  (setq doom-themes-enable-bold t
        doom-themes-enable-italic t)

  ;; Load the theme (choose my favorite).
  (load-theme 'doom-tomorrow-night t)

  ;; Enable flashing mode-line on errors.
  (doom-themes-visual-bell-config)

  ;; Corrects (and improves) org-mode's native fontification.
  (doom-themes-org-config))

(defvar my/theme-toggle-list '(doom-tomorrow-night doom-tomorrow-day)
  "Themes `my/toggle-theme' alternates between.")

(defun my/toggle-theme ()
  "Switch between the two themes in `my/theme-toggle-list'.
Disables whatever theme is currently active first, so themes
never stack."
  (interactive)
  (let* ((current (car custom-enabled-themes))
         (next (if (eq current (car my/theme-toggle-list))
                   (cadr my/theme-toggle-list)
                 (car my/theme-toggle-list))))
    (mapc #'disable-theme custom-enabled-themes)
    (load-theme next t)
    (message "Theme: %s" next)))

(global-set-key (kbd "C-c t") #'my/toggle-theme)
#+end_src

* Mode Line

A lightweight, no-dependency replacement for the default mode line.

mood-line deliberately omits minor-mode lighters, so ~prose-mode~'s
~" Prose"~ lighter would never appear. Since that mode substantially
changes how a buffer looks and behaves, we add a small custom segment
that surfaces it: ~mood-line-segment-prose~ returns an indicator only
while ~prose-mode~ is active (and nil otherwise, so mood-line drops
the segment and its separator entirely). It is spliced into a copy of
the default format on the right side, just before the major mode.

#+begin_src emacs-lisp
(use-package mood-line
  :config
  (defun mood-line-segment-prose ()
    "Mode-line indicator shown only while `prose-mode' is active."
    (when (bound-and-true-p prose-mode)
      (propertize "✍ Prose" 'face 'mood-line-status-info)))

  (setq mood-line-format
        (mood-line-defformat
         :left
         (((mood-line-segment-modal)                  . " ")
          ((or (mood-line-segment-buffer-status) " ") . " ")
          ((mood-line-segment-buffer-name)            . "  ")
          ((mood-line-segment-anzu)                   . "  ")
          ((mood-line-segment-multiple-cursors)       . "  ")
          ((mood-line-segment-cursor-position)        . " ")
          (mood-line-segment-scroll))
         :right
         (((mood-line-segment-prose)      . "  ")
          ((mood-line-segment-vc)         . "  ")
          ((mood-line-segment-major-mode) . "  ")
          ((mood-line-segment-misc-info)  . "  ")
          ((mood-line-segment-checker)    . "  ")
          ((mood-line-segment-process)    . "  "))))

  (mood-line-mode))
#+end_src

* Custom Keybindings

~C-c r~ reloads the configuration without restarting Emacs. It
loads ~user-init-file~ (~init.el~), which reloads ~custom.el~ and
then runs ~org-babel-load-file~ on ~config.org~ -- re-tangling it
to ~config.el~ (only when the org file is newer) and loading the
result into the running daemon. This is a named command rather
than an anonymous lambda so it is discoverable via ~M-x~ and
which-key, and self-documenting in this table.

Note this is an *additive* reload: it applies settings I add or
change, but does not undo things I remove (a deleted keybinding,
hook, or ~(mode 1)~ persists in the running image). For a
guaranteed-clean state, restart the daemon:
~systemctl --user restart emacs~.

#+begin_src emacs-lisp
(defun my/reload-config ()
  "Reload the Emacs configuration without restarting the daemon.
Loads `user-init-file', which reloads `custom.el' and re-tangles
and loads `config.org'.  Additive only: removed settings are not
undone until a full restart."
  (interactive)
  (load-file user-init-file)
  (message "Config reloaded from %s" (abbreviate-file-name user-init-file)))

(global-set-key (kbd "C-c r") #'my/reload-config)
#+end_src

** Consult

Enhanced, Vertico-aware replacements for several built-in commands:
they add live preview and richer sources on top of what's already
there. ~C-x b~ now runs ~consult-buffer~ instead of plain
~switch-to-buffer~ (also lists recent files and bookmarks), ~M-g g~
upgrades ~goto-line~, and ~M-g i~ upgrades ~imenu~, all keeping their
original default keys. ~M-s l~ searches the current buffer
(~consult-line~, like Vim's ~/~) and ~M-s r~ greps the project with
ripgrep (~consult-ripgrep~).

#+begin_src emacs-lisp
(use-package consult
  :init
  ;; Populates consult-buffer's "File" section with recently opened
  ;; files -- without this, recentf-mode is off by default and that
  ;; section stays empty.
  (recentf-mode 1)
  :bind
  (("C-x b" . consult-buffer)
   ("M-g g" . consult-goto-line)
   ("M-g i" . consult-imenu)
   ("M-s l" . consult-line)
   ("M-s r" . consult-ripgrep)))
#+end_src

* Navigation

** Avy

Jump to any visible text by typing a few characters: Avy overlays a
short key sequence on every match, and pressing that sequence moves
point straight there. Faster than repeated ~C-s~ or arrow/line
hopping for on-screen jumps.

- ~C-;~ types characters until I pause, then shows hints for every
  match (handles "two or more characters" queries).
- ~C-:~ jumps to an exact two-character match.
- ~M-g w~ jumps to a word by its first character(s).
- ~M-g l~ jumps to a line.

~C-'~ is deliberately avoided: =org-mode= binds it locally to
~org-cycle-agenda-files~, which would shadow a global Avy binding in
any Org buffer (including this file).

#+begin_src emacs-lisp
(use-package avy
  :bind
  (("C-;" . avy-goto-char-timer)
   ("C-:" . avy-goto-char-2)
   ("M-g w" . avy-goto-word-1)
   ("M-g l" . avy-goto-line)))
#+end_src

* Modal Editing

** God Mode

God-mode lets me invoke ~C-~/~M-~ bound commands without holding
modifier keys: while it's active, plain key presses are interpreted
as if Control were held (e.g. ~xf~ runs ~C-x C-f~), and a leading
~g~/~G~ switches the next key to Meta/Control-Meta.

The toggle is bound to ~<f13>~, a keysym no physical key normally
sends. Caps Lock is remapped by ~keyd~ (system-wide, see
=/etc/keyd/default.conf=) to send Control when *held* and F13 when
*tapped* — so Caps Lock keeps working as Control everywhere else on
the system, and a bare tap now toggles God mode in Emacs instead of
reaching for the far-away Escape key.

This machine's X11 keyboard model is ~pc105+inet~ (see
=/usr/share/X11/xkb/symbols/inet=), which remaps the physical F13
position to the ~XF86Tools~ keysym instead of plain F13 — some
toolkits report that event to Emacs as ~<Tools>~ rather than
~<XF86Tools>~. Both symbols are bound below so the toggle works
regardless of which name the display stack reports.

The cursor switches to a box while God mode is active and back to a

* Prose Writing

A distraction-free environment for long-form prose (a book, essays),
loosely modeled on Ulysses on macOS. Rather than hooking these into
every =org-mode= buffer -- which would drag agenda files, notes, and
this config itself into proportional fonts and a narrow column -- they
are bundled into a single ~prose-mode~ minor mode I toggle on
demand with ~C-c w~, or auto-enable per file with a "Local Variables"
footer (see below).

Three packages supply the pieces:

- *Olivetti* narrows and centers the text to a fixed column, the way
  Ulysses frames the page. ~olivetti-body-width~ is the column width
  in characters; 66 sits in the classic 45--75 "measure" for
  comfortable prose (80 reads long -- that's really a code width).
- *mixed-pitch* switches body text to a proportional font while
  keeping tables, code, and other fixed-pitch faces monospaced -- so
  prose reads like a book but structure stays aligned.
- *org-modern* restyles headings, lists, and markup for a cleaner,
  less-marked-up look.

#+begin_src emacs-lisp
(use-package olivetti
  :custom
  (olivetti-body-width 66))

(use-package mixed-pitch)

(use-package org-modern)
#+end_src

~prose-mode~ turns all three on together, plus soft line wrapping
(~visual-line-mode~) and typewriter-style scrolling that keeps the
current line near the vertical center (~scroll-conservatively~ with a
half-window ~maximum-scroll-margin~). Toggling it back off restores
each minor mode and clears the buffer-local scroll/spacing overrides
with ~kill-local-variable~, so the buffer returns to ordinary editing
rather than leaving stray locals behind.

Prose also runs one step larger than the default face via
~text-scale~ (buffer-local, so it never touches other buffers). The
Mac Studio already opens at an 18pt default, so it gets no bump;
=framework=, at ~13pt, gets a single ~text-scale-mode-step~ (~1.2x)
for a slightly more comfortable reading size. Because it is a
per-buffer zoom rather than a global font change, ~C-x C-=~ / ~C-x
C--~ still nudge it further while I write.

#+begin_src emacs-lisp
(defvar my/prose-text-scale
  (if (string-prefix-p "KevinsMacStudio" (system-name)) 0 1)
  "Extra `text-scale' steps `prose-mode' applies to the buffer.
Each step scales the buffer font by `text-scale-mode-step' (1.2x
by default).  KevinsMacStudio already runs a large 18pt default
face and gets no bump; framework gets one step over its ~13pt.")

(define-minor-mode prose-mode
  "Toggle a distraction-free prose writing environment.
Enables Olivetti, mixed-pitch, org-modern, soft line wrapping,
typewriter-style centered scrolling, and a buffer-local font bump
of `my/prose-text-scale' steps -- all in the current buffer only."
  :init-value nil
  :lighter " Prose"
  (if prose-mode
      (progn
        (olivetti-mode 1)
        (mixed-pitch-mode 1)
        (org-modern-mode 1)
        (visual-line-mode 1)
        (text-scale-set my/prose-text-scale)
        (setq-local line-spacing 0.3
                    scroll-conservatively 101
                    maximum-scroll-margin 0.5
                    scroll-margin 99999))
    (olivetti-mode -1)
    (mixed-pitch-mode -1)
    (org-modern-mode -1)
    (visual-line-mode -1)
    (text-scale-set 0)
    (kill-local-variable 'line-spacing)
    (kill-local-variable 'scroll-conservatively)
    (kill-local-variable 'maximum-scroll-margin)
    (kill-local-variable 'scroll-margin)))

(global-set-key (kbd "C-c w") #'prose-mode)
#+end_src

** Folding a Section From Its Body

Plain ~TAB~ / ~org-cycle~ only fold when point is *on* the heading

* Encrypted Files (EasyPG)

Emacs's built-in EasyPG Assistant (~epa-file~, enabled by default)
transparently *decrypts* any =.gpg= file when opened and *re-encrypts*
it on save. That -- not any generic save behavior -- is why editing
=~/.authinfo.gpg= (which holds the FreshRSS Fever password, see
[[*Elfeed + FreshRSS (synced RSS)][Elfeed + FreshRSS]]) pops up a recipient prompt: encrypting
needs to know whose key can decrypt the result.

By default it asks on every save. Pointing ~epa-file-encrypt-to~ at my
own key and setting ~epa-file-select-keys~ to nil (which, per its
docstring, means "ask only when no recipient is configured") makes it
encrypt silently to that key. This assumes a personal GPG key for
=hall@absinthe.org= exists --

: gpg --quick-generate-key "Kevin Hall <hall@absinthe.org>"

-- otherwise saving a =.gpg= file fails with "no public key". The
lone ExpressVPN key that ships in the keyring is unrelated and must
not be used as a recipient (its private key isn't ours).

#+begin_src emacs-lisp
(setq epa-file-encrypt-to '("hall@absinthe.org")
      epa-file-select-keys nil)
#+end_src

prompt back through Emacs's own minibuffer instead. It requires
~allow-loopback-pinentry~ in the machine-local =~/.gnupg/gpg-agent.conf=
(not tracked here). Guarded by ~system-type~ so the shared config
leaves the Linux box -- which already has a working graphical pinentry

* Email (notmuch + Fastmail)

Mail lives as a local Maildir at =~/Maildir/fastmail/=, kept in sync with
Fastmail by [[https://isync.sourceforge.io/][isync (~mbsync~)]] and indexed by
[[https://notmuchmail.org/][notmuch]]. notmuch itself neither fetches nor
sends mail -- it only indexes and tags -- so the moving parts are:

- *Fetch*  : ~mbsync -a~ pulls IMAP -> =~/Maildir/fastmail/= (config in =~/.mbsyncrc=).
- *Index*  : ~notmuch new~ indexes the Maildir and applies tags (config in =~/.notmuch-config=).
- *Send*   : ~msmtp~ -- Emacs's built-in ~smtpmail~ can't speak XOAUTH2, which
  Yale requires. Fastmail authenticates with the app password from
  =~/.authinfo.gpg=; Yale (Microsoft 365) with an OAuth2 token from
  =mutt_oauth2.py=. Emacs selects the account by From (config in =~/.msmtprc=).

Everything is portable to Linux: =~/.mbsyncrc= and =~/.msmtprc= use
~$HOME~-relative paths (only =~/.msmtprc='s ~tls_trust_file~ is OS-specific);
=~/.notmuch-config='s absolute ~database.path~ and the machine-local
=~/.authinfo.gpg= differ per machine.

** Secret handling

The Fastmail *app password* (created in Fastmail's web UI, distinct from the
web-login password) must never live in the dotfiles repo. It is stored once
in =~/.authinfo.gpg= (the same encrypted store the FreshRSS Fever password
uses), on two lines -- same app password for both IMAP and SMTP:

: machine imap.fastmail.com login hall@absinthe.org password APP-PASSWORD
: machine smtp.fastmail.com login hall@absinthe.org port 465 password APP-PASSWORD

~mbsync~ reads the IMAP line via its ~PassCmd~; ~msmtp~ reads the SMTP line via
its ~passwordeval~ (the Fastmail account in =~/.msmtprc=).

The ~notmuch~ Emacs package is pulled from ELPA (via ~use-package-always-ensure~)
rather than the copy Homebrew/apt ship with the CLI, so the same config loads
identically on every machine. ~C-c m~ opens the notmuch hello screen.

~notmuch-fcc-dirs~ files a copy of every sent message into the matching local
Sent maildir *by From address*, so Yale-sent mail lands in =yale/Sent Items=
and everything else in =fastmail/Sent=. The next ~mbsync~ uploads it (neither
Fastmail nor Office 365 auto-saves SMTP-sent mail server-side, so this Fcc is
what populates Sent). ~maildir:synchronize_flags~ in =~/.notmuch-config= means
read/flagged state round-trips: notmuch <-> Maildir flags <-> mbsync <-> server.

** Deleting mail (move to Fastmail Trash)

notmuch has no "delete" -- only tags. ~d~ tags a thread ~deleted~ (which
=search.exclude_tags= hides immediately) and advances. Nothing leaves
Fastmail at that instant. On the next sync the =pre-new= hook physically
moves every ~deleted~ message into the local Trash maildir, and ~mbsync~
relocates it to *Fastmail Trash* -- recoverable there until Fastmail
auto-purges (~30 days). Tagging ~deleted~ does **not** set the Maildir
~T~ flag (verified: notmuch only syncs D/F/P/R/S), so it never triggers an
IMAP expunge on its own; the *move* is what deletes it from the original
folder.

Undo is easy *before* the next sync: ~-deleted~ (or ~notmuch-search-tag~)
puts it right back. After the sync it lives in Fastmail Trash, so recover
it from any Fastmail client. These commands live in a
~with-eval-after-load~ block because they reference ~notmuch-*-mode-map~,
which only exist once notmuch has loaded.

#+begin_src emacs-lisp
(with-eval-after-load 'notmuch
  (defun my/notmuch-search-delete ()
    "Tag thread(s) `deleted' and advance; synced to Fastmail Trash on next poll."
    (interactive)
    (notmuch-search-tag '("+deleted" "-inbox" "-unread"))
    (notmuch-search-next-thread))

  (defun my/notmuch-show-delete ()
    "Tag the current message `deleted' and move to the next thread."
    (interactive)
    (notmuch-show-tag '("+deleted" "-inbox" "-unread"))
    (notmuch-show-next-thread t))

  (define-key notmuch-search-mode-map (kbd "d") #'my/notmuch-search-delete)
  (define-key notmuch-show-mode-map   (kbd "d") #'my/notmuch-show-delete))
#+end_src

** Auto-fetch every 5 minutes

While Emacs is running, poll Fastmail every 5 minutes in the *background*
(a detached ~notmuch new~, which runs the =pre-new= sync hook) and refresh
any open notmuch buffers when it finishes. Using ~make-process~ instead of
the built-in synchronous ~notmuch-poll~ keeps the ~mbsync~ round-trip off
the main thread, so the UI never freezes mid-sync. A guard skips a new run
while the previous one is still going (notmuch takes a database lock, so
overlapping runs would error), and the timer is cancelled-then-recreated on
every ~C-c r~ so reloads don't stack timers. Polling begins once notmuch is
first loaded in a session (i.e. after my first ~C-c m~).

~G~ (normally the built-in *synchronous* ~notmuch-poll-and-refresh-this-buffer~,
which blocks Emacs for the whole ~mbsync -a~ + index round-trip -- seconds, or
much longer when Office 365 throttles Yale) is rebound in the notmuch buffers to
trigger this *same* background poll. A manual sync then no longer freezes the
UI: ~G~ returns immediately and the open buffers refresh themselves when the
fetch finishes, exactly like the timer. Trade-off: results aren't guaranteed
present the instant ~G~ returns -- new mail appears a moment later on its own.

#+begin_src emacs-lisp
(with-eval-after-load 'notmuch
  (defvar my/notmuch-poll-process nil
    "The most recent background `notmuch new' process, or nil.")

  (defun my/notmuch-poll-async ()
    "Run `notmuch new' in the background, then refresh notmuch buffers."
    (when (or (null my/notmuch-poll-process)
              (not (process-live-p my/notmuch-poll-process)))
      (setq my/notmuch-poll-process
            (make-process
             :name "notmuch-poll" :buffer nil :noquery t
             :command (list notmuch-command "new")
             :sentinel (lambda (_proc event)
                         (when (string-prefix-p "finished" event)
                           (notmuch-refresh-all-buffers)))))))

  (defun my/notmuch-poll-refresh ()
    "Non-blocking replacement for `G' (`notmuch-poll-and-refresh-this-buffer').
Kick off the background `notmuch new' (see `my/notmuch-poll-async')
instead of the built-in synchronous poll, so a manual sync never freezes
the UI.  Open buffers refresh when the fetch finishes; if a poll is
already running, just say so rather than starting a second one."
    (interactive)
    (if (and my/notmuch-poll-process (process-live-p my/notmuch-poll-process))
        (message "notmuch: a background sync is already running…")
      (my/notmuch-poll-async)
      (message "notmuch: syncing mail in the background…")))

  (define-key notmuch-search-mode-map (kbd "G") #'my/notmuch-poll-refresh)
  (define-key notmuch-hello-mode-map  (kbd "G") #'my/notmuch-poll-refresh)
  (define-key notmuch-show-mode-map   (kbd "G") #'my/notmuch-poll-refresh)

  (defvar my/notmuch-poll-timer nil
    "Repeating timer that drives `my/notmuch-poll-async'.")
  (when (timerp my/notmuch-poll-timer) (cancel-timer my/notmuch-poll-timer))
  (setq my/notmuch-poll-timer
        (run-with-timer 300 300 #'my/notmuch-poll-async)))
#+end_src

* Elfeed + FreshRSS (synced RSS)

A feed reader whose read/unread state syncs with the self-hosted
FreshRSS instance (so what I read here is marked read everywhere):
[[https://github.com/skeeto/elfeed][Elfeed]] as the reader and
[[https://github.com/fasheng/elfeed-protocol][elfeed-protocol]] as the
sync layer, talking to FreshRSS over its *Fever API*. FreshRSS is the
source of truth for subscriptions -- feeds are managed there, not in
this file -- and elfeed just mirrors them, pushing read/starred
changes back immediately.

FreshRSS runs in a Proxmox LXC container and is reached over Tailscale
(~100.121.73.82~, the container's own tailnet address). Because Tailscale is already WireGuard-encrypted
end to end, plain HTTP over the tailnet is fine -- no TLS or
~--insecure~ curl flags needed.

** Secret handling

The Fever API password must *not* live in this file (it is tracked in
the dotfiles repo). It is read at load time from ~auth-source~
(=~/.authinfo.gpg=), keyed on the host and user below. Add a line like
this to =~/.authinfo.gpg= (or =~/.authinfo=):

: machine 100.121.73.82 login YOUR-FRESHRSS-USER password YOUR-FEVER-API-PASSWORD

If the lookup returns nil (password not yet stored) elfeed simply
won't authenticate until it is added -- nothing here breaks.

** Prerequisites (one-time, in FreshRSS)

1. FreshRSS → Settings → Authentication → tick *Allow API access*.
2. FreshRSS → Settings → Profile → set an *API password* (this is the
   Fever password, distinct from the web-login password) and put it in
   =~/.authinfo.gpg= as above.
3. Import the OPML into FreshRSS if not already, so it holds the feeds.

** Configuration

~my/freshrss-user~ must be set to the FreshRSS account name; it feeds
both the Fever URL and the auth-source lookup. ~C-c e~ opens Elfeed;
inside it, ~G~ fetches/syncs. Categories (the Feedbin folders) come
across as Elfeed tags via ~fetch-category-as-tag~.

Fever's incremental ~G~ only fetches *new* entries and only applies
read-state to what it fetches, so articles read on another device keep
a stale ~unread~ tag here (and ~elfeed-protocol-fever-reinit~ doesn't
fix it). ~my/elfeed-freshrss-clear-read~ (bound to ~C-c E~ in the
Elfeed search buffer) closes that gap: it pulls the server's live
~unread_item_ids~ set and mirrors it onto the local entries, so
reading elsewhere finally clears here. Run ~G~ for new articles, ~C-c
E~ to reconcile what I read on another device.

The search buffer's default line layout caps the title at
~elfeed-search-title-max-width~ (70) and left-packs the feed name after
it, wasting the right half of a wide frame. ~my/elfeed-search-print-entry~
replaces ~elfeed-search-print-entry-function~ to instead right-align the
feed+tags block to the window edge and let the title fill everything in
between -- so widening the frame widens the title, on one line. It keeps
the default faces and the ~kbd-help~ tooltip; only the geometry changes.

;; defconst, not defvar: these are edited in this file and must update
;; on `C-c r'.  `defvar' only assigns when the symbol is unbound, so once
;; the daemon has a value it ignores later edits until a full restart;
;; `defconst' reassigns on every load.
(defconst my/freshrss-host "100.121.73.82"
  "Host/IP of the FreshRSS instance, as reached over Tailscale.")

(defconst my/freshrss-user "hall"
  "FreshRSS account name, used for the Fever URL and auth-source lookup.")

(defun my/elfeed-freshrss-clear-read ()
  "Mirror FreshRSS read/unread state onto already-downloaded Elfeed entries.
elfeed-protocol's Fever sync only applies read-state to entries it
*fetches*, and `G' fetches only new ids -- so articles read on
another device keep a stale `unread' tag here, and
`elfeed-protocol-fever-reinit' does not fix it either.

This fetches the Fever `unread_item_ids' set directly and, for
every local entry carrying a Fever id, adds or removes the
`unread' tag to match the server -- locally only, via
`elfeed-tag-1'/`elfeed-untag-1', so nothing is pushed back.  The
Fever api_key is md5(user:password); the password comes from
auth-source, never from this file."
  (interactive)
  (let* ((host my/freshrss-host) (user my/freshrss-user)
         (pw (auth-source-pick-first-password :host host :user user))
         (key (md5 (concat user ":" pw)))
         (url (format "http://%s/api/fever.php?api&unread_item_ids" host))
         (url-request-method "POST")
         (url-request-extra-headers
          '(("Content-Type" . "application/x-www-form-urlencoded")))
         (url-request-data (concat "api_key=" key))
         (unread-set (make-hash-table :test 'eql)))
    (with-current-buffer (url-retrieve-synchronously url t t 30)
      (goto-char (point-min))
      (re-search-forward "\n\n" nil t)
      (let* ((json (json-parse-buffer :object-type 'alist))
             (ids (alist-get 'unread_item_ids json)))
        (unless (eql 1 (alist-get 'auth json))
          (user-error "FreshRSS Fever auth failed"))
        (dolist (id (split-string (or ids "") "," t))
          (puthash (string-to-number id) t unread-set))))
    (let ((cleared 0) (marked 0))
      (with-elfeed-db-visit (entry _feed)
        (let ((id (elfeed-meta entry :id)))
          (when id
            (if (gethash id unread-set)
                (unless (elfeed-tagged-p 'unread entry)
                  (elfeed-tag-1 entry 'unread) (setq marked (1+ marked)))
              (when (elfeed-tagged-p 'unread entry)
                (elfeed-untag-1 entry 'unread) (setq cleared (1+ cleared)))))))
      (elfeed-db-save)
      (when (get-buffer "*elfeed-search*")
        (with-current-buffer "*elfeed-search*" (elfeed-search-update :force)))
      (message "FreshRSS reconcile: cleared %d read, marked %d unread; %d unread on server"
               cleared marked (hash-table-count unread-set)))))

  (defun my/elfeed-search-print-entry (entry)
    "Print ENTRY like the elfeed default, but right-align feed+tags.
The date and title stay on the left; the feed name and tag list are
pinned to the window's right edge, and the title column expands to
fill the gap between them.  Widening the frame widens the title."
    (let* ((date  (elfeed-search-format-date (elfeed-entry-date entry)))
           (title (or (elfeed-meta entry :title) (elfeed-entry-title entry) ""))
           (title-faces (elfeed-search--faces (elfeed-entry-tags entry)))
           (feed  (elfeed-entry-feed entry))
           (feed-title (when feed (or (elfeed-meta feed :title)
                                      (elfeed-feed-title feed))))
           (tags  (mapcar #'symbol-name (elfeed-entry-tags entry)))
           (tags-str (concat "(" (mapconcat
                                  (lambda (s) (propertize s 'face 'elfeed-search-tag-face))
                                  tags ",")
                             ")"))
           (right (concat (when feed-title
                            (propertize feed-title 'face 'elfeed-search-feed-face))
                          " " tags-str))
           ;; Leave room for the date, its trailing space, the right-hand
           ;; block, and a one-column gap; floor at 16 so a narrow window
           ;; still shows something.
           (title-width (max 16 (- (window-width)
                                   (string-width date)
                                   (string-width right)
                                   3)))
           (title-column (elfeed-format-column title title-width :left)))
      (insert (propertize date 'face 'elfeed-search-date-face) " ")
      (insert (propertize title-column 'face title-faces 'kbd-help title) " ")
      (insert right)))
  (setq elfeed-search-print-entry-function #'my/elfeed-search-print-entry)
  ;; `elfeed-show' renders articles with shr; an image taller than the
  ;; window makes the default SPC/DEL (`scroll-up/down-command') jump
  ;; clear past it, so entries with big images are hard to read (see
  ;; `pixel-scroll-precision-mode' in Basic UI).  Remap paging to pixel

  (with-eval-after-load 'elfeed-show
    (define-key elfeed-show-mode-map (kbd "SPC")   #'pixel-scroll-interpolate-down)
    (define-key elfeed-show-mode-map (kbd "S-SPC") #'pixel-scroll-interpolate-up)
    (define-key elfeed-show-mode-map (kbd "DEL")   #'pixel-scroll-interpolate-up)))

* Web Browsing (eww)

~eww~ renders HTML with ~shr~, no JavaScript. It will never match a real
browser, but a few ~shr~ defaults make ordinary pages far more readable:

- ~shr-use-colors nil~ -- the biggest win. By default ~shr~ paints each page's
  *own* colours, which often clash with the theme (washed-out low-contrast
  text). Off, pages use my theme's faces, so contrast is consistent everywhere
  ~shr~ renders (eww, HTML mail in notmuch, Elfeed article bodies).
- ~shr-max-width 90~ (from 120) -- wrap body text to a readable column instead
  of stretching across the whole frame.
- ~shr-max-image-proportion 0.6~ (from 0.9) -- keep hero images and publisher
  logos from dominating the viewport.

Per-page keys still apply: ~R~ (~eww-readable~) re-renders just the extracted
article, and ~M-I~ (~eww-toggle-images~) hides images for a text-only read.
~eww-readable-urls~ takes a list of URL regexps to auto-apply the readable view
on sites I read often -- left empty here to fill in per taste. (JavaScript
aggregators like news.google.com only expose fallback markup and stay poor;
for news *feeds*, Elfeed above is the better tool.)

#+begin_src emacs-lisp
(use-package shr
  :ensure nil
  :config
  (setq shr-use-colors nil
        shr-max-width 90
        shr-max-image-proportion 0.6))

(use-package eww
  :ensure nil
  :config
  ;; Add URL regexps here to auto-apply `eww-readable' on sites read often,
  ;; e.g. '("nytimes\\.com/" "apnews\\.com/").
  (setq eww-readable-urls nil))
#+end_src

** Nicer rendering, readable Org, and a real browser

Three upgrades layered on top of eww:

- *shrface* re-skins ~shr~'s output with Org-like headings, real paragraph
  typography, bullet lists, and ~TAB~ folding + ~imenu~ navigation -- a big
  visual jump for eww, Elfeed article bodies, and HTML mail (anything ~shr~
  renders). ~shrface-basic~ installs its handlers into
  ~shr-external-rendering-functions~; ~shrface-mode~ (added to
  ~eww-after-render-hook~) adds the outline/navigation.
- *org-web-tools* fetches a URL, runs readability, and converts the article
  into a clean *Org buffer* (headings, links, no chrome) -- the best
  distraction-free read of a content-in-HTML page. ~M-x
  org-web-tools-read-url-as-org~. Needs =pandoc= for the HTML->Org conversion.
- *xwidget-webkit* is a real embedded WebKit engine (this build is
  ~--with-xwidgets~) for the JavaScript-heavy pages ~eww~ can't render at all.
  In eww, ~W~ reopens the current page in WebKit; ~M-x
  xwidget-webkit-browse-url~ opens any URL directly. (Paywalls/logins still
  apply -- it behaves like a browser.)

(defun my/eww-open-in-xwidget ()
  "Reopen the current eww page in an embedded WebKit (xwidget) view."
  (interactive)
  (let ((url (eww-current-url)))
    (unless url (user-error "No current eww URL"))
    (xwidget-webkit-browse-url url)))
