#+AUTHOR: E. Kevin Hall
#+STARTUP: showall

* What this is

Step-by-step notes for rebuilding my Emacs email stack (Fastmail + Yale) on a
*new machine* (macOS or Linux). Most of it travels in these dotfiles and is
installed with *GNU Stow* — =config.org=, =~/.mbsyncrc= (both accounts), the
notmuch hooks, and =~/.local/bin/mutt_oauth2.py=. What Stow can NOT carry —
the secrets, a compiled SASL binary, and the one machine-specific config path
(=~/.notmuch-config=) — is recreated by hand; every such file is flagged
throughout and summarised in [[*Files at a glance (what's where)]].

** Architecture (four moving parts)

notmuch does not fetch or send mail — it only indexes and tags a local
Maildir. The stack:

| Job                   | Tool                       | Config file                         |
|-----------------------+----------------------------+-------------------------------------|
| Fetch IMAP -> Maildir | ~mbsync~ (isync)           | =~/.mbsyncrc=                       |
| Index + tag           | ~notmuch~                  | =~/.notmuch-config= + Maildir hooks |
| Send                  | ~msmtp~ (XOAUTH2 for Yale) | =~/.msmtprc= (+ config.org routing) |
| Secrets               | ~gpg~ + =~/.authinfo.gpg=  | machine-local                       |

Mail is stored at =~/Maildir/fastmail/=. The notmuch database indexes the
whole of =~/Maildir/= (so more accounts can be added later as siblings).

* Quick checklist for a new machine

Most config comes from the repo via Stow; only the secrets, the SASL binary,
and =~/.notmuch-config= are created by hand.

1. [ ] Install packages incl. =stow= (see [[*1. Install packages]]).
2. [ ] Clone dotfiles and stow both packages — installs =config.org=,
   =~/.mbsyncrc= (both accounts), the notmuch hooks, and =mutt_oauth2.py=:
   : git clone https://github.com/ekhall/dotfiles ~/dotfiles
   : cd ~/dotfiles && stow --no-folding emacs mail
3. [ ] Ensure =~/.local/bin= is on =$PATH= (see [[*1. Install packages]]) — the
   mbsync PassCmd calls =mutt_oauth2.py= by bare name.
4. [ ] GPG key for =hall@absinthe.org=; macOS also needs loopback pinentry (see [[*2. GPG key]]).
5. [ ] Create a Fastmail app password (see [[*3. Fastmail app password]]) and write it
   into =~/.authinfo.gpg= (see [[*4. Secrets]]).
6. [ ] Write =~/.notmuch-config= — set =database.path= for this OS (see [[*6. notmuch config]]).
7. [ ] *Yale:* Python cert fix (macOS), =mutt_oauth2.py --authorize=, and build the
   =cyrus-sasl-xoauth2= plugin (see [[*Second account: Yale (Microsoft 365 via OAuth2)]]).
8. [ ] First sync, index, and the one-time retro-tag (see [[*8. First sync and index]] and Yale step 5).
9. [ ] In Emacs: =C-c r= then =C-c m= (see [[*9. Emacs]]).

* 1. Install packages

** macOS (Homebrew)

#+begin_src sh
brew install isync notmuch gnupg stow
#+end_src

Binaries land in =/opt/homebrew/bin= (Apple Silicon). Emacs picks them up
via =exec-path-from-shell= (already configured in =config.org=).

** Linux (Debian/Ubuntu)

#+begin_src sh
sudo apt install isync notmuch gnupg stow
#+end_src

Arch: =sudo pacman -S isync notmuch gnupg stow= (full package set and the
Arch-specific deltas: [[*Linux (Arch) — deltas from the macOS path]]).
Fedora: =sudo dnf install isync notmuch gnupg2 stow=.

The Emacs ~notmuch~ package is installed from *MELPA* by =use-package= on
first launch, so you do NOT need the distro's =notmuch-emacs= package. (The
CLI ~notmuch~ IS required — that's what the ELPA package drives.)

** =~/.local/bin= must be on =$PATH=

The Yale mbsync PassCmd calls =mutt_oauth2.py= by *bare name*, so both your
shell and Emacs (which inherits PATH via =exec-path-from-shell=) need
=~/.local/bin= on =PATH=. If it isn't already, add to =~/.zshrc= / =~/.bashrc=:

#+begin_src sh
export PATH="$HOME/.local/bin:$PATH"
#+end_src

Then restart Emacs so it re-inherits the shell PATH. (Symptom if missing: Yale
sync fails with a PassCmd / "command not found" error, Fastmail still works.)

* 2. GPG key

=~/.authinfo.gpg= is encrypted to my personal key. If this machine has no
key for =hall@absinthe.org= yet:

#+begin_src sh
gpg --quick-generate-key "Kevin Hall <hall@absinthe.org>"
#+end_src

To reuse the *same* key across machines (nicer — one identity everywhere),
export it on an existing box and import here:

#+begin_src sh
# on the old machine:
gpg --export-secret-keys --armor hall@absinthe.org > secret.asc
# copy secret.asc over a trusted channel, then on the new machine:
gpg --import secret.asc && rm -P secret.asc   # macOS; Linux: shred -u secret.asc
#+end_src

A per-machine key is also fine — each box generates its own =hall@absinthe.org=
key and =~/.authinfo.gpg= is written fresh on that machine (Fastmail app
password + FreshRSS Fever password re-entered locally). Nothing then needs the
old key. This mac (=MWC9JXJTGDXD=) was set up that way.

** macOS only: loopback pinentry

A GUI =Emacs.app= has no controlling TTY, so gpg-agent cannot prompt for the
key passphrase and decryption fails. =config.org= already sets
=epa-pinentry-mode 'loopback= on macOS, but that also requires this line in
the machine-local =~/.gnupg/gpg-agent.conf=:

#+begin_src conf
allow-loopback-pinentry
#+end_src

Then =gpgconf --kill gpg-agent= (or just re-login). On Linux with a working
graphical pinentry under the desktop session this is not needed.

Loopback covers *Emacs's own* =.gpg= access (authinfo, elfeed). It does NOT
help the background =mbsync= poll, whose =PassCmd= runs =gpg= / =mutt_oauth2.py=
directly — outside Emacs — so those still need gpg-agent to decrypt
non-interactively. With only the default 10-minute cache, the Yale poll starts
failing once the cache lapses (=Difficulty decrypting token file...= from
=mutt_oauth2.py=; Fastmail's =PassCmd= fails the same way).

** macOS: pinentry-mac for unattended decryption (recommended)

The robust fix is =pinentry-mac=: a native passphrase dialog that can store the
passphrase in the login Keychain, so both GUI Emacs and the background poll
authenticate without prompting.

#+begin_src sh
brew install pinentry-mac
#+end_src

Add to =~/.gnupg/gpg-agent.conf= (keep =allow-loopback-pinentry= for Emacs):

#+begin_src conf
pinentry-program /opt/homebrew/bin/pinentry-mac
#+end_src

Then =gpgconf --kill gpg-agent=. On the next decrypt (e.g. =mbsync -a=) the
dialog appears once — enter the passphrase and tick *Save in Keychain*; it is
then unattended. This supersedes the "prime the agent manually" workaround for
Yale gotcha #3. (Linux uses its desktop pinentry; not needed there.)

* 3. Fastmail app password

Fastmail requires an *app-specific password* for IMAP/SMTP (the normal login
password will not work, especially with 2FA).

1. Fastmail web UI -> *Settings -> Password & Security -> App Passwords*.
2. *New App Password*, name it e.g. =emacs-notmuch=, scope it to *Mail
   (IMAP/SMTP)*.
3. Copy the generated password (looks like =abcd-efgh-ijkl-mnop=).

Each machine can have its own app password (recommended — revoke per device),
or share one. Never paste it into a chat or commit it anywhere.

* 4. Secrets (=~/.authinfo.gpg=)

Open the (new or existing) encrypted authinfo in Emacs so EasyPG handles the
crypto: =C-x C-f ~/.authinfo.gpg=. Add these two lines (same app password on
both), then =C-x C-s= (re-encrypts to the =hall@absinthe.org= key):

#+begin_src text
machine imap.fastmail.com login hall@absinthe.org password YOUR-APP-PASSWORD
machine smtp.fastmail.com login hall@absinthe.org port 465 password YOUR-APP-PASSWORD
#+end_src

- ~mbsync~ reads the IMAP line via its =PassCmd= (an inline gpg+awk pipeline).
- ~msmtp~ reads the SMTP line via its =passwordeval= (the Fastmail account).

Sanity check the extraction (does not reveal the secret):

#+begin_src sh
gpg -q --for-your-eyes-only --no-tty -d ~/.authinfo.gpg \
 | awk '/machine imap.fastmail.com/{for(i=1;i<=NF;i++) if($i=="password") print "IMAP pw length="length($(i+1))}'
#+end_src

* 5. mbsync config (=~/.mbsyncrc=)

*Comes from =stow mail=* — you don't hand-write this on a machine using the
dotfiles repo. The live file already holds *both* accounts: the Fastmail block
below, plus the Yale channel shown in the Yale section (step 4). The block
below is the Fastmail half, kept for reference and for bootstrapping a box that
isn't using the repo. Portable as-is (=$HOME=-relative); if TLS verification
fails on a fresh Homebrew box, uncomment the matching =CertificateFile= line.

#+begin_src conf
# ~/.mbsyncrc — Fastmail <-> local Maildir sync for notmuch
IMAPAccount fastmail
Host imap.fastmail.com
Port 993
User hall@absinthe.org
# Pull the password field from the imap.fastmail.com line in .authinfo.gpg.
PassCmd "gpg -q --for-your-eyes-only --no-tty -d ~/.authinfo.gpg | awk '/machine imap.fastmail.com/{for(i=1;i<=NF;i++) if($i==\"password\") print $(i+1)}'"
TLSType IMAPS
AuthMechs LOGIN
# If TLS verification fails, uncomment the matching path:
# CertificateFile /opt/homebrew/etc/openssl@3/cert.pem   # macOS (Apple Silicon)
# CertificateFile /etc/ssl/certs/ca-certificates.crt     # Linux

IMAPStore fastmail-remote
Account fastmail

MaildirStore fastmail-local
Subfolders Verbatim
Path ~/Maildir/fastmail/
Inbox ~/Maildir/fastmail/Inbox

Channel fastmail
Far :fastmail-remote:
Near :fastmail-local:
Patterns *
Create Near
Expunge Both
SyncState *
CopyArrivalDate yes
#+end_src

Requires isync >= 1.4 for the =Far=/=Near= keywords (1.5.x confirmed). On
very old distros that ship isync 1.3, use =Master=/=Slave= instead.

* 6. notmuch config (=~/.notmuch-config=)

*Machine-local — NOT stowed* (its =database.path= is absolute and differs per
OS, so it can't be a shared symlink). Create it by hand. The ONLY line that
changes per machine is =database.path=:

- macOS: =/Users/<you>/Maildir=
- Linux: =/home/<you>/Maildir=

This is the *complete, current* file (covers both accounts):

#+begin_src conf
[database]
path=/home/hall/Maildir          # <-- macOS: /Users/hall/Maildir

[user]
name=E. Kevin Hall
primary_email=hall@absinthe.org
other_email=kevin.hall@yale.edu

[new]
tags=new;unread
ignore=.mbsyncstate;.mbsyncstate.new;.mbsyncstate.journal;.uidvalidity;.DS_Store;Calendar;Contacts;Journal;Outbox;Conversation History;Sync Issues

[search]
exclude_tags=deleted;spam

[maildir]
synchronize_flags=true
#+end_src

* 7. notmuch hooks

*Come from =stow mail=* — =~/Maildir/.notmuch/hooks/{pre-new,post-new}= become
symlinks into the repo, so you don't hand-create them on a machine using the
dotfiles. The *live* hooks tag *both* accounts and OS-guard =SASL_PATH=; the
blocks below are the Fastmail-base reference (the Yale =post-new= rules are in
the Yale section, step 5). If bootstrapping without the repo, create them and:

#+begin_src sh
mkdir -p ~/Maildir/.notmuch/hooks
chmod +x ~/Maildir/.notmuch/hooks/pre-new ~/Maildir/.notmuch/hooks/post-new
#+end_src

** pre-new — flush deletions to Trash, then fetch

Runs before every =notmuch new= (Emacs =G=, the 5-min timer, manual runs).

#+begin_src sh
#!/bin/sh
# pre-new: (1) flush deletions to Fastmail Trash, then (2) fetch mail.
# macOS: Yale's XOAUTH2 SASL plugin lives in a user dir (Linux uses the system
# dir, so SASL_PATH must not be set there).
[ "$(uname)" = "Darwin" ] && export SASL_PATH="$HOME/.local/lib/sasl2"
TRASH_DIR="$HOME/Maildir/fastmail/Trash/cur"
mkdir -p "$TRASH_DIR"

# (1) Move `deleted`-tagged mail (not already in Trash) into the Trash maildir.
#     mbsync then relocates it to Fastmail Trash (recoverable ~30 days).
#     Strip isync's ",U=<n>" so the moved file is treated as a NEW Trash msg.
notmuch search --output=files 'tag:deleted and not path:fastmail/Trash/**' 2>/dev/null \
| while IFS= read -r src; do
    [ -f "$src" ] || continue
    base=$(basename "$src")
    dst=$(printf '%s' "$base" | sed -E 's/,U=[0-9]+//')
    mv -n "$src" "$TRASH_DIR/$dst"
  done

# (2) Fetch + push (propagates moves + flag changes; pulls new mail).
mbsync -a || true
#+end_src

** post-new — map Fastmail folders to tags

Runs after every =notmuch new=. NOTE: the folder names below are specific to
*this Fastmail account*. Verify them on first sync with
=ls ~/Maildir/fastmail/= and adjust if the account differs. Uses
=path:.../**= (not =folder:=) because =folder:= does not match names with
spaces (e.g. "Junk Mail").

#+begin_src sh
#!/bin/sh
# post-new: map Fastmail folder location -> notmuch tags, then clear "new".
set -e
notmuch tag +inbox          -- 'tag:new and path:fastmail/Inbox/**'
notmuch tag +archive        -- 'tag:new and path:fastmail/Archive/**'
notmuch tag +draft          -- 'tag:new and path:fastmail/Drafts/**'
# This account has three legacy Sent folders (Fastmail / Outlook / Apple Mail):
notmuch tag +sent -unread   -- 'tag:new and (path:fastmail/Sent/** or path:"fastmail/Sent Items/**" or path:"fastmail/Sent Messages/**")'
notmuch tag +spam    -inbox -- 'tag:new and path:"fastmail/Junk Mail/**"'
notmuch tag +deleted -inbox -- 'tag:new and path:fastmail/Trash/**'
notmuch tag -new -- tag:new
#+end_src

* 8. First sync and index

#+begin_src sh
mkdir -p ~/Maildir/fastmail
mbsync -a          # first run prompts once for the GPG key passphrase
ls ~/Maildir/fastmail/   # confirm folder names match the post-new hook
notmuch new        # indexes everything and runs the hooks
#+end_src

Verify:

#+begin_src sh
notmuch count '*'            # total messages
notmuch count tag:inbox      # should roughly match the Inbox folder
notmuch count tag:unread
#+end_src

The first =mbsync= downloads the entire mailbox and can take several minutes;
the first =notmuch new= indexes all of it (a couple of minutes).

* 9. Emacs

The mail config is already in =config.org= (section "Email (notmuch +
Fastmail)"). Nothing to copy — just load it:

- =C-c r=  — re-tangle + load =config.org=.
- =C-c m=  — open notmuch. Saved searches: =j i= inbox, =j u= unread, etc.
- =G=      — fetch + index + tag (also runs automatically every 5 min).
- =d=      — delete (moves to Fastmail Trash on next sync; undo with =-deleted=).
- =C-c C-c= in a compose buffer — send via Fastmail SMTP.

See =~/Desktop/notmuch-cheatsheet.pdf= for the full key map. It is generated
from =emacs/.emacs.d/notmuch-cheatsheet.html= in this repo (a self-contained,
print-styled one-pager). To regenerate the PDF after editing the HTML, render
it with headless Chrome:

#+begin_src sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
  --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="$HOME/Desktop/notmuch-cheatsheet.pdf" \
  "$HOME/dotfiles/emacs/.emacs.d/notmuch-cheatsheet.html"
#+end_src

* How deletion and sending actually work

- *Delete*: =d= tags a thread =deleted= (hidden immediately via
  =search.exclude_tags=). Tagging =deleted= does NOT set any Maildir flag
  (notmuch only syncs D/F/P/R/S), so it does nothing to Fastmail by itself.
  On the next sync the =pre-new= hook *moves* the file into the Trash
  maildir, and mbsync relocates it to Fastmail Trash — recoverable there
  until Fastmail auto-purges (~30 days). Undo before the next sync with
  =-deleted=.
  *Yale caveat:* this move-to-Trash is Fastmail-only (the hook targets
  =fastmail/Trash=). Deleting a *Yale* message only tags it =deleted= and
  hides it locally — it stays in the Outlook Inbox on the server. A Yale
  delete-move into Outlook's "Deleted Items" (via a push channel) is not built.
- *Send*: =msmtp= submits the mail (=~/.msmtprc=); Emacs picks the account
  from the From header. Fastmail uses =smtp.fastmail.com:465= (app password);
  Yale uses =smtp.office365.com:587= XOAUTH2 (OAuth token). *Sent copy:*
  Fastmail does not save SMTP-sent mail, so it gets a local Fcc into
  =fastmail/Sent= that the next sync uploads; Yale (Office 365) auto-saves sent
  mail into its Exchange =Sent Items= server-side, so its Fcc is skipped and
  the next sync just pulls the server copy down.
- *Read/flag state* round-trips: notmuch tags <-> Maildir flags <-> mbsync
  <-> server (=synchronize_flags=true=).

* Second account: Yale (Microsoft 365 via OAuth2)

Yale is Microsoft 365. Basic-auth IMAP is dead there; it requires *OAuth2*.
IMAP *is* enabled on the mailbox, but only works with a token minted against
*Yale's tenant* (not the generic ~common~ endpoint). No DavMail and no Yale
IT involvement are needed. Beyond the Fastmail stack this adds three things:
a token manager (=mutt_oauth2.py=), a SASL XOAUTH2 plugin so ~mbsync~ can
authenticate, and a second mbsync channel + notmuch tags.

** Read these gotchas first (each cost hours)

1. *Tenant, not ~common~.* The token MUST use Yale's tenant GUID
   =dd8cbebb-2139-4df8-b411-4e3e87abeb5c=. A ~common~-tenant token
   authenticates but IMAP then fails with *"User is authenticated but not
   connected"* — that is NOT "IMAP disabled", it's the wrong tenant.
2. *macOS system XOAUTH2 is incompatible with mbsync.* Apple's
   =/usr/lib/sasl2/oauthbearer.so= advertises XOAUTH2 but wants a callback
   ~mbsync~ can't supply (=Unable to find a callback: 18948=). Use the
   moriyoshi =cyrus-sasl-xoauth2= plugin (takes the token via the ordinary
   password callback). Apple's libsasl2 honours =SASL_PATH=, so the plugin
   can live in a user-owned dir — no SIP fight.
3. *gpg-agent must decrypt non-interactively.* ~mbsync~'s PassCmd runs
   =mutt_oauth2.py=, which decrypts the token with gpg. For unattended runs
   (Emacs poll), prime the agent: set =GPG_TTY=$(tty)= in a terminal, or use
   =pinentry-mac= / a long =default-cache-ttl=.

** 2. Token manager: mutt_oauth2.py

  https://raw.githubusercontent.com/muttmua/mutt/master/contrib/mutt_oauth2.py

#+end_src

Edit its =microsoft= registration:
- =ENCRYPTION_PIPE= recipient -> =hall@absinthe.org=
- =client_id= -> =9e5f94bc-e8a4-4e73-b8be-63364c29d753= (Thunderbird's public app; Yale permits it)
- =tenant= AND the =authorize_endpoint= / =devicecode_endpoint= / =token_endpoint=

Authorize (interactive browser sign-in with NetID + MFA) and test:

#   want: IMAP/POP/SMTP authentication succeeded
#+end_src

** 3. cyrus-sasl-xoauth2 plugin

*** macOS (from source; not in Homebrew)

#+begin_src sh
brew install libtool automake
cd ~/.local/opt && git clone --depth 1 https://github.com/moriyoshi/cyrus-sasl-xoauth2.git
cd cyrus-sasl-xoauth2
glibtoolize --force --copy               # NOT libtoolize on macOS
touch NEWS README AUTHORS ChangeLog      # automake strict mode wants these
autoreconf -fvi && ./configure && make   # SDK provides sasl/*.h automatically

# Assemble a private plugin dir: our XOAUTH2 + symlinks to the system plugins,
# but EXCLUDING Apple's oauthbearer.so (whose XOAUTH2 we're replacing).
mkdir -p ~/.local/lib/sasl2
for f in /usr/lib/sasl2/*.so; do
  b=$(basename "$f"); [ "$b" = oauthbearer.so ] && continue
  ln -sf "$f" ~/.local/lib/sasl2/"$b"
done
cp .libs/libxoauth2.0.so ~/.local/lib/sasl2/libxoauth2.so   # name must be libxoauth2.so
#+end_src

mbsync then needs =SASL_PATH=$HOME/.local/lib/sasl2= in its environment.

*** Linux (easier — no SASL_PATH, no conflict)

#+begin_src sh
sudo apt install libsasl2-dev autoconf automake libtool   # + build-essential git
git clone --depth 1 https://github.com/moriyoshi/cyrus-sasl-xoauth2.git
cd cyrus-sasl-xoauth2 && ./autogen.sh && ./configure && make && sudo make install
#+end_src

This installs into the system SASL dir (=/usr/lib/x86_64-linux-gnu/sasl2/=),
and Linux libsasl2 has no conflicting Apple plugin, so =SASL_PATH= is *not*
needed there. (Omit the =SASL_PATH= export from the hook on Linux, or point
it at the system dir.)

** 6. Make the auto-poll authenticate Yale

The =pre-new= hook exports =SASL_PATH= before =mbsync -a= so the Emacs 5-min
poll (and =G=) can auth Yale, not just Fastmail. It is OS-guarded, so it's a
no-op on Linux (where the plugin is in the system SASL dir):

: [ "$(uname)" = "Darwin" ] && export SASL_PATH="$HOME/.local/lib/sasl2"

** Sending as Yale (msmtp + XOAUTH2)

Sending *is* wired up now. Emacs's built-in =smtpmail= can't speak XOAUTH2,
so delivery is handed to =msmtp= (=brew install msmtp=; config =~/.msmtprc=,
=chmod 600=, machine-local, holds no secrets — it uses =passwordeval=). Two
accounts:

- *fastmail* — =smtp.fastmail.com:465=, app password pulled from
  =~/.authinfo.gpg= (same gpg+awk pipeline as mbsync; use a regex field match
  =$i ~ /^password$/= to avoid the double-quote escaping msmtp mangles).
- *yale* — =smtp.office365.com:587= STARTTLS, =auth xoauth2=, token from
  =mutt_oauth2.py ~/.mutt_oauth2_yale.token= (the same token as IMAP).

=config.org= routes message-mode through =message-send-mail-with-sendmail= ->
=msmtp=, and =my/choose-msmtp-account= (on =message-send-mail-hook=) picks
=-a yale= vs =-a fastmail= from the From header. =notmuch-fcc-dirs= is an alist
keyed on From: Fastmail Fccs to =fastmail/Sent=; Yale's entry is =nil= (no local
Fcc) because Office 365 auto-saves sent mail to Exchange =Sent Items= itself --
mbsync just pulls it down. (A local Yale Fcc would duplicate the server copy and
trip the =notmuch insert= DB lock -- the "Insert failed" prompt on send.)

Verify without sending: =msmtp --serverinfo -a yale= (expect =XOAUTH2= under
AUTH) and =-a fastmail=. Then send a real test to yourself from each identity.
GnuTLS-backed msmtp needs a CA bundle: =tls_trust_file /etc/ssl/cert.pem= on
macOS.

** Security note

During setup the Yale OAuth tokens were exposed in a chat transcript. Re-mint
before relying on this: =rm ~/.mutt_oauth2_yale.token= then re-authorize
(without =--debug=), and revoke old sessions at =myapplications.microsoft.com=.

* Optional: OS-level background sync (mail while Emacs is closed)

The Emacs timer only runs while Emacs is open. To sync in the background
regardless, add a timer (not currently used — the Emacs poll is enough):

** macOS — launchd LaunchAgent

Create =~/Library/LaunchAgents/io.archetyp.notmuch-sync.plist= running
=mbsync -a && notmuch new= every 300s, then =launchctl load= it.

** Linux — systemd user timer

Create =~/.config/systemd/user/notmuch-sync.service= (Type=oneshot running
=mbsync -a && notmuch new=) plus a =notmuch-sync.timer= with

* Linux (Arch) — deltas from the macOS path

Notes from building this stack on the Arch box. The stowed config (=config.org=,
=~/.mbsyncrc=, hooks, vdirsyncer) is portable and needed *no* changes; everything
below is either a package name, a machine-local file, or a gotcha.

** Packages (one line)

#+begin_src sh
sudo pacman -S --needed isync notmuch gnupg stow msmtp vdirsyncer python-pipx
pipx install ical2orgpy          # not in the Arch repos; lands in ~/.local/bin
#+end_src

The cyrus-sasl headers (=/usr/include/sasl/sasl.h=) and the autotools chain come
with =base-devel= + =cyrus-sasl=, which a normal Arch install already has -- the
XOAUTH2 plugin built with no extra deps.

** Create the Maildir roots BEFORE the first sync

The single thing that actually broke here. isync does not create a
=MaildirStore='s top-level =Path=: =Create Near= only creates mailboxes *under*
an existing store root. With =~/Maildir/yale/= absent, =mbsync -a= prints

: Maildir error: cannot open store '/home/hall/Maildir/yale'

and *skips the whole Yale channel* while Fastmail syncs fine -- and because the
=pre-new= hook ends in =mbsync -a || true=, the failure is swallowed and
=notmuch new= happily indexes zero Yale mail. Symptom is a silent =tag:yale= of 0.
So, once per account:

#+begin_src sh
mkdir -p ~/Maildir/fastmail ~/Maildir/yale
#+end_src

** cyrus-sasl-xoauth2 -> system SASL dir (no SASL_PATH)

As the Yale section says, Linux needs no =SASL_PATH= and has no conflicting Apple
plugin. On Arch it installs into =/usr/lib/sasl2/=:

#+begin_src sh
cd ~/.local/opt && git clone --depth 1 https://github.com/moriyoshi/cyrus-sasl-xoauth2.git
cd cyrus-sasl-xoauth2 && ./autogen.sh && ./configure && make && sudo make install
#+end_src

Note it is =./autogen.sh= (not =glibtoolize=) and =libxoauth2.so= keeps its
libtool name -- no manual rename/symlink farm like the macOS build. Verify with
=msmtp --serverinfo -a yale=: XOAUTH2 must appear under the auth methods.

** msmtp CA bundle

=tls_trust_file /etc/ssl/cert.pem= is the *macOS* path. On Arch use:

: tls_trust_file /etc/ssl/certs/ca-certificates.crt

(a symlink to =/etc/ca-certificates/extracted/tls-ca-bundle.pem=).

** GPG

Nothing to do: the desktop pinentry under a graphical session decrypts
=~/.authinfo.gpg= and the OAuth token fine for both Emacs and the background
poll. No =allow-loopback-pinentry=, no =pinentry-mac= equivalent needed.
=config.org= only sets =epa-pinentry-mode 'loopback= on macOS.

** Indexing a big backlog without re-triggering a multi-hour mbsync

=notmuch new= runs =pre-new=, which runs =mbsync -a= -- so re-indexing an
already-downloaded backlog would re-drive the whole (throttled) Yale sync first.
To index mail that is already on disk, skip the hooks and apply the tag rules by
hand afterwards (=post-new= only acts on =tag:new=, which the fresh index sets,
so the result is identical):

#+begin_src sh
notmuch new --no-hooks          # index only; no fetch
~/Maildir/.notmuch/hooks/post-new   # folder -> tag rules, then clears `new'
#+end_src

** Yale first sync is slow

Office 365 throttled the initial pull hard: ~9 hours for the first pass, which
ended in =Socket error ... timeout= after finishing only the Inbox. That is the
expected behaviour flagged in the Yale section -- re-running =mbsync yale=
resumes and picks up the remaining folders. Final state on this box: ~32k Yale
messages (=Archive*= stays server-side by the =Patterns= exclusion, as designed).

* Troubleshooting / gotchas learned during setup

- *Newest-first didn't stick from the global var* (root cause found; was
  "unexplained" for a long time). =notmuch-lib.el= declares the variable with
  =(make-variable-buffer-local 'notmuch-search-oldest-first)=, so a plain
  =(setq notmuch-search-oldest-first nil)= in =config.org= only ever created a
  *buffer-local* binding in whichever buffer was current while =config.el=
  loaded — the *global* default stayed at its shipped value of =t=. And
  =notmuch-search= reads =(default-value 'notmuch-search-oldest-first)=
  explicitly, deliberately ignoring buffer-local overrides, so every ad-hoc
  search (=s= from hello, or =M-x notmuch-search=) came back oldest-first.
  The saved searches looked fine throughout because each pins its own
  =:sort-order newest-first=, which masked the real problem. *Fix:*
  =setq-default=, not =setq=. Note sort order is still buffer-local per search
  buffer — press =o= to flip one, or kill and reopen it after changing the
  default.
- *"text is read-only" when pressing a saved-search letter.* On the hello /
  search buffers, the letters (=i=, =u=, ...) are =notmuch-jump= shortcuts:
  press =j= first, then the letter. A bare letter tries to type into a
  read-only buffer.
- *=folder:= returns 0 for folders with spaces* (e.g. "Junk Mail"). Use
  =path:"fastmail/Junk Mail/**"= instead. This is why the hooks use =path:=.
- *isync stores its UID in the maildir filename* as =,U=<n>=. When moving a
  message between folders by hand (or in the pre-new hook), strip that field
  or isync mis-maps the moved file.
- *mbsync PassCmd hangs / no prompt.* The GPG passphrase isn't cached; run a
  =gpg -d ~/.authinfo.gpg= once in a terminal to prime gpg-agent, and (macOS)
  ensure loopback pinentry is set up. Better long-term fix on macOS: install
  =pinentry-mac= and save the passphrase to Keychain (see [[*macOS: pinentry-mac for unattended decryption (recommended)]]).
- *(macOS, not mail) Emacs won't launch after a Homebrew upgrade* —
  =dyld: Library not loaded: .../libMagickWand-7.Q16HDRI.NN.dylib=. =emacs-plus=
  is built against ImageMagick's current soname; a later =brew upgrade= that
  bumps ImageMagick's ABI (e.g. compat 11↔12, soname =.10=↔=.11=) leaves the
  binary linked to a version that no longer exists. A symlink can't bridge a
  *major* ABI change. Rebuild against the installed ImageMagick with the same
  options it was installed with (check =INSTALL_RECEIPT.json=):
  : brew reinstall emacs-plus@30 --with-xwidgets --with-imagemagick --with-mailutils
  Also note =/Applications/Emacs.app= is a real =cp -r= copy per the emacs-plus
  caveats, so a rebuild won't refresh it; this mac instead symlinks it
  (=/Applications/Emacs.app -> /opt/homebrew/opt/emacs-plus@30/Emacs.app=) so
  future rebuilds are picked up automatically.

* Calendars in org-agenda (read-only: iCloud + Yale/Outlook)

Both calendars are mirrored read-only into Org files that org-agenda reads.
=vdirsyncer= fetches each into =~/.calendars/=; =ical2orgpy= converts them to
=~/org/calendars/*.org= (one =#+CATEGORY= per calendar); an Emacs timer
(=my/calendar-sync= in =config.org=) reruns the sync every 30 min. iCloud uses
CalDAV (=caldav.icloud.com=, app-specific password); Yale uses a published-ICS
URL, since Office 365 has no CalDAV.

** Install

: brew install vdirsyncer pipx
: pipx install ical2orgpy

** Stow

=stow --no-folding calendars= installs =~/.config/vdirsyncer/{config,
icloud-pw.sh,sync-calendars.sh}=. =--no-folding= so the machine-local files
below coexist beside them as real files.

** Machine-local files (recreate by hand; gitignored)

1. *iCloud app password* -- appleid.apple.com -> Sign-In and Security ->
   App-Specific Passwords. Add to =~/.authinfo.gpg=:
   : machine caldav.icloud.com login <apple-id> password <app-password>
2. *Yale published-ICS URL* -- Outlook web -> Settings -> Calendar -> Shared
   calendars -> Publish a calendar -> copy the ICS link. Store it (no newline):
   : printf '%s' '<ics-url>' > ~/.config/vdirsyncer/yale-ics-url
   The stowed =config= reads it via =url.fetch=, keeping the token out of the
   repo. (If Yale disables publishing, switch to the Microsoft Graph API.)
3. *iCloud calendar-name map* (=icloud-names.tsv=, gives readable =#+CATEGORY=)
   -- regenerate from discovery:
   : vdirsyncer discover icloud </dev/null 2>&1 \
   :   | grep -oE '"[^"]+" \("[^"]+"\)' \
   :   | sed -E 's/^"([^"]+)" \("([^"]+)"\)$/\1\t\2/' > ~/.config/vdirsyncer/icloud-names.tsv

** First sync

: yes | vdirsyncer discover icloud     # confirm creating local collections
: yes | vdirsyncer discover yale
: ~/.config/vdirsyncer/sync-calendars.sh   # sync + convert -> ~/org/calendars/

Then =C-c a= in Emacs opens the agenda (=g= forces a refresh). The Org files
under =~/org/calendars/= are generated -- never hand-edit them.

* Rust (rust-ts-mode + eglot)

Everything Emacs-side is built-in and travels in =config.org= automatically
(see [[file:config.org::*Rust][config.org: Rust]] for how
~rust-ts-mode~/~eglot~/~flymake~ fit together). Two things are NOT bundled
with Emacs and need installing per
machine: the Rust toolchain itself, and the tree-sitter grammar (a small
compiled parser library, unrelated to the language server -- see config.org
for that distinction).

** Install the Rust toolchain

: curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
: rustup component add rust-analyzer

This puts =rustc=, =cargo=, and =rust-analyzer= on =PATH= via
=~/.cargo/bin= (added to shell =PATH= by rustup's own installer; restart the
shell/Emacs afterward so =exec-path-from-shell= -- see [[*Inherit the shell PATH (macOS)][config.org]] -- picks it up).

** Tree-sitter grammar (built automatically)

=config.org='s Rust section calls ~treesit-install-language-grammar~ itself
the first time Emacs loads with no Rust grammar present, so there is nothing
to run by hand -- it needs Git, a C compiler, and network access (all already
required/available per [[*1. Install packages]]). It compiles to
=~/.emacs.d/tree-sitter/= (gitignored -- machine-specific binary, not carried
in the repo). To force a rebuild (e.g. after a tree-sitter ABI change),
delete that directory and reload =config.org=.

* Clojure (clojure-ts-mode + CIDER + eglot)

Everything Emacs-side travels in =config.org=
(see [[file:config.org::*Clojure][config.org: Clojure]] for how
~clojure-ts-mode~ / CIDER / ~clojure-lsp~ divide the work). Per machine, two
external binaries need installing; a third is optional.

** Install the Clojure toolchain (macOS, Homebrew)

: brew install clojure/tools/clojure
: brew install clojure-lsp/brew/clojure-lsp-native
: brew install borkdude/brew/babashka        # optional: fast scripting (bb)

- =clojure= -- the official Clojure CLI (~clj~ / ~clojure~). This is what
  CIDER's ~cider-jack-in-clj~ shells out to; it pulls in a JVM (=openjdk=)
  as a Homebrew dependency automatically.
- =clojure-lsp-native= -- the language server eglot starts (static
  analysis + clj-kondo diagnostics; no REPL needed). Must be on =PATH=
  for GUI Emacs, which it is via Homebrew + exec-path-from-shell
  (see [[file:config.org::*Inherit the shell PATH (macOS)][config.org]]).

Linux: =clojure= and =clojure-lsp= from the distro repos (Arch:
~pacman -S clojure clojure-lsp~), or the official install scripts.

Verify (first run resolves deps over the network, so it's slow once):

: clj -M -e '(println "ok")'

** Tree-sitter grammar (built automatically)

Even more hands-off than Rust: ~clojure-ts-mode~ fetches and compiles its
own grammar on first use (needs Git + a C compiler, already required per
[[*1. Install packages]]); nothing to run by hand, and no recipe stanza in
=config.org= either. Compiles into the same gitignored
=~/.emacs.d/tree-sitter/=.

** First jack-in is slow (once)

The first ~C-c C-x j j~ in a project downloads CIDER's injected nREPL
dependencies through the Clojure CLI; later jack-ins hit the local Maven
cache (=~/.m2/=) and start in a few seconds.

* Elixir & Phoenix (elixir-ts-mode + eglot)

Everything Emacs-side travels in =config.org= (see
[[file:config.org::*Elixir & Phoenix][config.org: Elixir & Phoenix]] --
the major modes are bundled with Emacs 30, so the only MELPA package is
=inf-elixir=). Per machine you need the Elixir toolchain and a language
server; the tree-sitter grammars build themselves.

** Install the Elixir toolchain (macOS, Homebrew)

: brew install elixir

Gives =elixir=, =mix=, and =iex= (pulling in Erlang/OTP as a dependency).
On =/opt/homebrew/bin=, so GUI Emacs sees it via exec-path-from-shell
(see [[file:config.org::*Inherit the shell PATH (macOS)][config.org]]).

Linux (Arch): ~pacman -S elixir~. Verify: ~elixir -v~.

Phoenix itself is *not* a system install -- it's a Mix archive plus per-project
deps:

: mix local.hex --force
: mix archive.install hex phx_new --force

** Install a language server (pick one)

=config.org= tries, in order, =expert=, =elixir-ls=, =language_server.sh=,
=start_lexical.sh=, and uses the first found on =PATH=. ~expert~ is the
official one the Elixir team is consolidating on and the one to prefer:

: brew install expert          # or: download a release binary, chmod +x, put on PATH

If Homebrew has no formula on this machine, grab the platform binary from
[[https://github.com/elixir-lang/expert/releases][elixir-lang/expert releases]],
name it =expert=, and drop it in =~/.local/bin= (already on =PATH= per
[[*=~/.local/bin= must be on =$PATH=]]). ~elixir-ls~ (=brew install elixir-ls=)
works too and needs no config change.

Check what Emacs will find: ~M-x eglot~ in an =.ex= buffer, or from a shell
~which expert elixir-ls language_server.sh~.

** Tree-sitter grammars (built automatically)

Same as Rust, but *two* of them -- =elixir= and =heex=. =config.org= installs
either one that's missing on load (needs Git, a C compiler, and network access
per [[*1. Install packages]]); they compile into the gitignored
=~/.emacs.d/tree-sitter/=. The =heex= one is what highlights Phoenix templates
*and* the ~~H"""..."""~ sigils inside LiveView =.ex= files; without it those
sigil bodies silently render as plain strings. To force a rebuild, delete the
=.dylib=/=.so= and reload =config.org=.

** First server start is slow (once)

The first ~eglot~ connection in a project compiles the whole dependency tree
into =_build/= before diagnostics appear -- minutes on a fresh Phoenix app,
seconds afterwards.

* Fonts (per-machine — none of these travel in the repo)

Font *files* are machine state, not config: =config.org= only names families
and degrades gracefully when one is missing (see
[[file:config.org::*Fonts][config.org: Fonts]]). So a new machine looks
progressively better as these are installed, and never breaks without them.

** Nerd Font symbols — needed for icons

Run once, from inside Emacs:

: M-x nerd-icons-install-fonts

Then restart Emacs. Without it, every icon in the mode line
([[file:config.org::*doom-modeline (active)][doom-modeline]]), the minibuffer,

: brew install --cask font-jetbrains-mono-nerd-font

SF Mono is bundled inside Xcode and Terminal but is not registered as a
system font other apps can resolve by name. Apple distributes both
standalone at [[https://developer.apple.com/fonts/]]; install if you want
SF Mono as the mono fallback and SF Pro Text for prose
([[file:config.org::*Prose Writing][prose-mode]]).
